## Executive Summary

Five bugs CONFIRMED, all reproduced deterministically and independently re-verified. None is data-corrupting or crash-looping; severity cluster is **P2 (conditional)/P3**:

1. **BUG-001** — shutdown/grace re-cancellation interrupts `GlobalHub.run()` mid-unwind, truncating upstream stream `__aexit__` cleanup (second `CancelledError` beats gated teardown).
2. **BUG-002** — ASGI `http.response.start` failure after SSE admission leaks subscriber slots (and the token-route flush task); cap exhaustion → 503 for later consumers until process restart.
3. **BUG-003** — `ReplayLog.append()` records `last_seq` before the fallible `size_of()` call; failure burns a sequence number and can trigger false `replay_expired` resync (latent; default sizer currently infallible).
4. **BUG-004 / BUG-005** — CPython 3.11+ 4300-digit `int()` conversion limit: oversized `?v=` selector and `Last-Event-ID` sequence digits raise uncaught `ValueError` → plain HTTP 500 instead of coded 400 / contract-mandated ignore-reset.

Zero bugs fixed (audit-only per mission rules); repair plan in §Repair Plan.

## Verified Bugs

### BUG-001 — Grace/close re-cancellation truncates `GlobalHub.run()` stream cleanup

- **Severity**: P2 (low-frequency — 30 s grace window, but slow/stuck teardown is precisely the risk state; impact: upstream connection not cleanly closed, resource hold until process exit)
- **Confidence**: High (lane 30-rep probe + orchestrator 3-scenario ×10 + mechanism proof)
- **Source Location**: `src/oc_slimapi/sse/registry.py:334-350` (`_remove_hub_after_grace` cancels all not-done children unconditionally), `:479-506` (`close()` cancels hub tasks + `_removal_task`; cancelling the in-progress removal gather re-propagates into `run()`), guarded counterpart at `src/oc_slimapi/sse/global_hub.py:371-393` (deliberately skips already-cancelling tasks — the rule registry paths violate); stream ownership `global_hub.py:1375-1472` (`async with self.client.stream(...)` at `:1385-1389`).
- **Missing Test Scenario**: grace-removal in flight ∩ `HubRegistry.close()` ∩ assert `run()` reached stream `__aexit__` completion.
- **Trigger**: hub idle → grace timer fires → `run()` begins unwinding and parks in stream-exit cleanup → `close()` (or overlapping second grace pass) cancels it again.
- **Execution Path**: `close()` → `hub.task.cancel()` direct re-cancel AND `close()` → `self._removal_task.cancel()` → parent `asyncio.gather(...)` cancellation propagates a second `CancelledError` into the unwinding `run()` → inner cleanup `await` aborts → `__aexit__` truncated.
- **Minimal Reproduction**: `/tmp/opencode/state_sequence_probe.py` (real `GlobalHub.run()` overlap: cancel count 1→3, stream exit completed 0/30); orchestrator `/tmp/opencode/ss1_final.py` (FakeStreamHub ×10: control cleanup=True 10/10; overlap cleanup=False 10/10, registry state consistent) + `/tmp/opencode/ss1_step5.py` (parent-gather cancel → `second_injected=True`, mechanism proof).
- **Commands Executed**: `.venv/bin/python /tmp/opencode/ss1_final.py`; `.venv/bin/python /tmp/opencode/ss1_step2.py` … `ss1_step5.py`; targeted `.venv/bin/python -m pytest tests/test_zombie_hub_revival.py -q` (28 passed).
- **Expected**: sole-canceller invariant — once cancellation is delivered, no second cancel until cleanup completes (as `global_hub.py:371-393` already enforces).
- **Actual**: second cancellation delivered mid-cleanup; cleanup segment never completes while registry drops the hub (tasks done, state consistent — silent truncation).
- **Repeatability**: 30/30 (lane), 10/10 per scenario (orchestrator), deterministic under event gating.
- **Root Cause**: registry-layer cancel paths lack the `task.cancelling()` guard used elsewhere; additionally, cancelling the removal task's parent gather re-injects into children — filtering direct `cancel()` alone is insufficient.
- **Impact**: leaked/half-closed upstream connections on shutdown under load or slow network teardown; no user-visible data corruption.
- **Relevant Git Context**: `8654d5b` hardened teardown but not this overlap.
- **Recommended Regression Test**: pytest-asyncio: arm grace with `GRACE_SECONDS=0`, drive `run()`-stub to stream-exit gate, call `registry.close()`, assert stub's post-gate cleanup flag is True and `cancel_count == 1`.
- **Recommended Fix Direction**: in `_remove_hub_after_grace` and `close()`, skip `cancel()` when `task.cancelling() > 0` (mirror `global_hub.py:371-393`), and await removal/child gathers with shielded or `return_exceptions=True` semantics that cannot re-inject into unwinding tasks; verify with the regression test.
- **Independent Reproduction**: Yes — orchestrator (this session) after lane discovery; all three scenario families reproduce.

### BUG-002 — Response-start failure after SSE admission leaks subscriber slot (+ token flush task)

- **Severity**: P3 (installed Uvicorn; conditional P2 where a raising transport/ASGI server wrapper is in front)
- **Confidence**: High (24/24 one-shot leaks, 12/12 cap-exhaustion batches, independent lane 120 embedded requests)
- **Source Location**: `src/oc_slimapi/routes/events.py:88-105` (admit) vs `:193-200` (only cleanup, in generator `finally`), response built `:208-212`; `src/oc_slimapi/routes/token_stream.py:102-120` (admit) vs `:209-213` cleanup, `:225-229` response. Framework facts pinned: Starlette 1.3.1 `responses.py:248-278` sends `http.response.start` before body iteration; unstarted generator's `aclose()` does NOT run `finally`.
- **Missing Test Scenario**: failure injected exactly at response-start send (before body generator first `__anext__`).
- **Trigger**: transport write error / ASGI server exception during `http.response.start`.
- **Execution Path**: route admits subscriber → returns `StreamingResponse` → Starlette `__call__` → `send({"type": "http.response.start"})` raises → generator never started → `finally` never entered → subscriber (and token `_flush_task`) retained in hub registries.
- **Minimal Reproduction**: `/tmp/opencode/repro_fi001_independent.py`; installed-Uvicorn boundary `/tmp/opencode/probe_uvicorn_start_send.py` (`OSError: INDEPENDENT_UVICORN_TRANSPORT_WRITE` escapes at response-start).
- **Commands Executed**: one-shot ×24 → ledger `control_total=1/control_set=1` each; token `token_total=1/token_flush_live=True`; batch ×12 (10 requests each) → statuses `[200×8, 503×2]`, `current=8/rejected=2`.
- **Expected**: admission rolled back on response-start failure.
- **Actual**: slot consumed until process shutdown; cap exhaustion rejects subsequent subscribers (503 `subscriber_capacity`).
- **Repeatability**: deterministic, 100%.
- **Alternative Explanations ruled out**: ASGI 2.4 `OSError→ClientDisconnect` translation still leaks (tested); already-disconnected Uvicorn returns silently (no trigger) — leak requires raising transport, hence conditional severity.
- **Root Cause**: cleanup tied solely to generator lifecycle; admission happens before response start.
- **Impact**: memory + admission-cap exhaustion under adversarial/erroring transport; recovery only via restart.
- **Relevant Git Context**: admission ordering unchanged since `573fc2d`/`786d8fb`.
- **Recommended Regression Test**: ASGI app double-call harness whose `send` raises on `http.response.start`; assert hub subscriber count returns to 0 and token flush task absent after exception propagates.
- **Recommended Fix Direction**: wrap admission in the response-send path — e.g. move subscribe into the generator prologue, or add an ASGI wrapper that catches send-time exceptions pre-first-chunk and calls the same detach routine used in `finally`.
- **Independent Reproduction**: Yes — reproduction lane (fresh session), plus framework-source pinned evidence.

### BUG-003 — `ReplayLog.append()` burns sequence on `size_of()` failure → false `replay_expired`

- **Severity**: P3 latent (default sizer `len()`-on-bytes currently infallible; defect triggers for custom fallible sizers or future payload shapes)
- **Confidence**: High (5/5 global + 5/5 token lane; 2/2 orchestrator-adjacent runs)
- **Source Location**: `src/oc_slimapi/sse/replay_log.py:404-406` (`_order += 1`; `state.last_seq = seq` **before** `self._size_of(payload)`), rollback `:465-483` requires `seq > state.last_seq` (false after mutation); callers `src/oc_slimapi/sse/tokenstream/fanout.py:184-246`, `GlobalHub._replay_publish` / `TokenStreamHub._publish_seq_frame`.
- **Missing Test Scenario**: `size_of` raising **after** seq assignment.
- **Trigger**: fallible size computation exception.
- **Execution Path**: append assigns seq → `size_of` raises `OSError("INJECTED_REPLAY_SIZE_FAILURE")` → caller catches, rollback no-ops → next frame gets seq 2; replay cursor 0 sees gap → `ReplayResync(reason="replay_expired")`.
- **Minimal Reproduction**: `/tmp/opencode/repro_fi002_independent.py` (`FailOnceSizer`).
- **Commands Executed**: after failure `last_seq=1, frames=0`; next success emits id `g:...:2` / `t:s-fi002:...:2`; replay from 0 → resync. Controls: pre-append failure rolls back (10/10); default sizer dense (10/10).
- **Expected**: documented rollback restores contiguity (promise from `09c0359`).
- **Actual**: phantom seq burned; false `replay_expired`.
- **Repeatability**: deterministic, 100%.
- **Root Cause**: state mutation ordered before fallible computation; rollback predicate invalidated by same mutation.
- **Impact**: today latent; future fallible sizing (or payload encoding change) silently degrades all reconnecting clients to full resync.
- **Relevant Git Context**: `09c0359` rollback lane B; its test fails `append` pre-mutation only.
- **Recommended Regression Test**: `size_of` stub raising on 2nd call; assert after failed append `last_seq == 0`-equivalent (rollback effective) and next frame reuses seq 1.
- **Recommended Fix Direction**: compute `size_of` (and any fallible step) before mutating `_order`/`state.last_seq`; only then commit; keep rollback for post-commit I/O.
- **Independent Reproduction**: Yes.

### BUG-004 — `?v=` selector ≥4301 digits → uncaught `ValueError` → HTTP 500

- **Severity**: P3 (robustness/contract shape; no memory/CPU blowup — 4.3 KiB request under h11 16 KiB budget)
- **Confidence**: High (3 full runs, real Uvicorn/h11 TCP reproduction)
- **Source Location**: grammar accepts `[1-9][0-9]*` `src/oc_slimapi/selector.py:127-128`; unguarded `int(values[0])` `:547-567`.
- **Trigger**: `GET /slimapi/...?v=<4301+ digits>`.
- **Execution Path**: parse OK → `int()` hits CPython 3.11+ `sys.set_int_max_str_digits()` limit (4300 on this 3.14 runtime) → `ValueError: Exceeds the limit (4300 digits) for integer string conversion: value has 4301 digits; use sys.set_int_max_str_digits() to increase the limit` → uncaught → plain 500.
- **Minimal Reproduction**: `/tmp/opencode/boundary_reproduction_probe.py` (4299/4300 → coded 400 `unsupported_version`; 4301 → 500); real-socket run confirms h11 accepts 4319-byte target.
- **Expected**: 400 `unsupported_version` (contract-consistent).
- **Actual**: 500.
- **Repeatability**: 3/3 complete runs; boundary exact at 4300/4301.
- **Root Cause**: digit-limit class (`int()` on adversarial-length decimal) re-introduced at selector site (cf. historical F-013).
- **Recommended Regression Test**: parametrized digit-length 4299/4300/4301/5000 → expect coded 400 all.
- **Recommended Fix Direction**: length-guard selector digits (e.g. `len(s) > 19 → invalid` before `int()`) or wrap `int()` in try/except ValueError → invalid version path.
- **Independent Reproduction**: Yes (reproduction lane, fresh session, 375/375 targeted green around it).

### BUG-005 — `Last-Event-ID` ≥4301-digit seq → same `ValueError` → 500, violating ignore/reset contract

- **Severity**: P3
- **Confidence**: High (global + token forms, zeros and leading-zero variants, 9/9 route attempts → 500; real h11 accepts 4320/4330-byte headers)
- **Source Location**: `_SEQ_RE = re.compile(r"^[0-9]+$")` `src/oc_slimapi/sse/replay_wire.py:67-71`; unguarded `int(seq_text)` in `parse_last_event_id` `:114-154`; parsed before admission on both SSE routes.
- **Trigger**: `Last-Event-ID: g:<epoch>:<4301+ digits>` (or `t:<sid>:<epoch>:<seq>`).
- **Expected** (contract `docs/specs/v4-contract.md:261,269-270`): malformed/unusable IDs ignored or reset — never request failure.
- **Actual**: plain 500.
- **Repeatability**: deterministic 100%.
- **Root Cause**: same digit-limit class; regex has no length bound.
- **Recommended Regression Test**: parametrized 4300/4301-digit (and all-zero) seq forms → expect default-cursor reset behavior, not 500.
- **Recommended Fix Direction**: bound seq digit length (≤19 safe for uint63 semantics) in `_SEQ_RE` or guard `int()` with try/except → treat as invalid cursor (reset).
- **Independent Reproduction**: Yes.
- **Note**: BUG-004/005 share one root pattern; a shared helper (guarded decimal parse) fixes both classes and any future sites.
