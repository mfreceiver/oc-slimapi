# oc-slimapi 权威接口映射

> 本文按当前实现生成，代码基线为 `src/oc_slimapi/`。它描述“现在实际做什么”，不把设计文档中的未实现项写成既有行为。

> **Aligned with v3-contract.md（M3 v3-only 终态，2026-08-16）**

> **⚠ v3-only 终态（M3）**：v2 wire 语义整体退役。`/slimapi/**` 唯一合法入口是 `?v=3`；无 `v`、`v=2`、合法但不支持的值 → 400 `{"code":"unsupported_version","supported":[3]}`。`X-Slimapi-Version` 头已删除（出现不报错也不解读）；`X-Next-Cursor`/`X-Complete`/`X-Slimapi-Subscriber-ID` 永不产出（messages/sessions 列表恒 envelope：`{"items":[…],"nextCursor"}` / `{"items":[…],"complete"}`）；消费集 `X-Opencode-Directory` 头出现 → 400 `directory_header_retired`（canonical 通道 = `?directory=`）；Vary 全路由收缩为 `Accept-Encoding` 单值；catch-all 反代**关闭**（未收编路径 404 `thin_route_not_found`）。下文各行中 v2 时代的加性注记（"须带 X-Slimapi-Version"、"未 bump 仍 2"、Vary 双值、X-* 辅助头、catch-all fallback 等）一律以本段终态声明为准。

## 0. 全局约束

- sidecar 监听 host 由 `OC_SLIMAPI_HOST` 决定（默认 `127.0.0.1:4097`，可选 `0.0.0.0:4097` 作为明文直连入口）；应用层没有 Basic/Bearer 鉴权。入站鉴权由 sidecar 前的 stunnel mTLS（`:14097` 推荐）完成；若用 `0.0.0.0` 明文直连，安全由 Tailscale ACL / 防火墙负责。
- upstream 由 `config.py` 固定为 loopback HTTP，默认 `http://127.0.0.1:4096`，请求参数不能改 upstream，禁止 SQLite。
- `app.py` 先按 `health → versions → agent → command → sessions → messages → events → metrics → questions → permissions → directories → token_stream` 注册 `/slimapi/**`（`token_stream` 在 catch-all 之前以确保不被 `/{path}` 吞掉），最后调用 `install_proxy(app)`（终态仅注册 WS 501 stub 与已关闭的 catch-all 404 兜底，见 §4 catch-all 行）。
- **版本选择器（v3-only 终态，`selector.py::SlimapiSelectorMiddleware`）**：`/slimapi/**` 解析 query `v`：词法 `^[1-9][0-9]*$`，`0`/`03`/`+3`/` 3`/`3.0`/空串/多值异值→400 `{"code":"invalid_version_selector"}`；多值同值折叠；`v=3`→v3 管线（剥离 `v` + directory 消费 §5.2/§5.7）；**无 `v`、`v=2`、合法但不支持（1/2/4/5…）→400 `{"code":"unsupported_version","supported":[3]}`**（v2 管线与 `OC_SLIMAPI_V3_SELECTOR_ENABLED` 回退开关已随 v2 删除）。`v` 参数对无条件剥离、永不转发，其余参数逐字节保持（编码/顺序/重复项/空段）。`GET /slimapi/versions` 归一化路径**无条件豁免**（不解析 `v`）；非 GET→405+`Allow: GET`（优先级高于一切）。终态错误优先级链（契约 §8.3）：①405→②selector 400→③directory 400（多值 `invalid_directory_selector`→双现异值 `directory_conflict`→消费集头出现 `directory_header_retired`）→④404 `thin_route_not_found`。
- `json_response()` honor `Accept-Encoding: gzip`，返回 `Content-Encoding:gzip` 和 `Vary:Accept-Encoding`；SSE、full 流式响应和多数上游错误透传不调用该 helper。
- `require_directory()` **已删除**（**v0.3.0** directory allowlist gate 全面移除）。directory 经 `normalize_directory()`（去尾斜杠，根 `/`）后作为 `X-Opencode-Directory` 头 + `?directory=` query 透传给上游 opencode；opencode 决定能否服务。allowlist 数据集已移除，**不再 gate**。保留的结构性守卫：显式 repeated `?directory=` 去重保序 + `invalid_directory_count`（1–32）+ messages `/**` 的 query `directory` 与 `X-Opencode-Directory` 头冲突 → 400 `directory_not_allowed`（结构性歧义）。**[3.3.0] B4-4 部署型 allowlist（新，与 v0.3.0 旧全局 gate 无关）**：`OC_SLIMAPI_DIRECTORY_ALLOWLIST` env 三态——未配置=现状零变化；显式空=机制启用（`/slimapi/file/**` 三端点全 403 `directory_not_allowed` + 启动 warning）；非空=realpath 解析后子树过滤（防 `..`/symlink 绕过；`/file` 组 fail-closed + GlobalHub SSE digest/IMMEDIATE 帧未知目录丢弃 + `allowlist_dropped_events` 计数 + health `features.allowlist:{enabled,droppedEvents?}` 广播）。语义权威 = v3-contract §5.7a；仅作用于 `/file` 组与 SSE 事件帧，其余端点不受影响。
- FastAPI 参数/body 校验失败的实际状态是 **422**；业务校验主动抛出的错误通常是 400/502/503/504。
- **客户端标识输入头（2026-07-29 加性）**：客户端**可选**发 `X-Client-Name` / `X-Client-Version` / `X-Client-Id`（大小写不敏感）。sidecar 读取后落入 access log 的 `client`/`clientVer`/`clientId` 字段（缺省 `null`）。（v2 catch-all 曾在转发前显式 pop 这三个头；终态 catch-all 已关闭，任何非 `/slimapi/**` 请求都不再被转发，三个头只用于 access log 落盘。）校验：空/空白→忽略；UTF-8 字节>128→忽略；含控制字符（`<0x20`/`0x7f`）→忽略；重复同名→取首个有效值。设备 id 默认 `sha256(raw)[:16]` hash 落盘（`OC_SLIMAPI_CLIENT_ID_SALT` 设置时升级为 `hmac_sha256(salt, raw)[:16]`）；`client`/`clientVer` 不 hash。
- **access log 文件发现规则（2026-07-29 加性，ops 面）**：由旧 `logs/access.jsonl`（`RotatingFileHandler` 10MiB×5）改为**按天切分** `access-YYYY-MM-DD.jsonl`。启动压缩**早于今天（`< today`）**的 `.jsonl` → `.gz`（原子 `.gz.tmp`+rename）+ 迁移**当前 `access_log_dir` 内**无日期文件为 `access-legacy-*.jsonl.gz`（**不跨目录迁移**；生产从旧相对目录升到 `StateDirectory` 时旧位置历史日志需运维手动移动）；后台 maintenance loop（默认 1h）周期 compress+prune（`OC_SLIMAPI_ACCESS_LOG_RETAIN_DAYS`，默认 `0`=不删；prune 严格匹配 `access-YYYY-MM-DD.jsonl(.gz)`，**不含** `access-legacy-*.jsonl.gz`——后者永久保留）。生产 systemd unit 覆盖路径到 `StateDirectory`（`%S/oc-slimapi/logs`）；本地开发默认相对 `logs/`。旧 env `OC_SLIMAPI_ACCESS_LOG_PATH` 标 deprecated（保留兼容）；`_MAX_BYTES`/`_BACKUPS` 已于 **1.1.5** 移除（不再读取）。

## 5. Skeleton 精确规则

消息由 `skeleton_messages()` / `skeleton_message()` 转换；`info` 深拷贝完整保留，parts 由 `skeleton_part()` 分派：

| part.type | 当前处理 |
|---|---|
| `text` | 整 part 深拷贝，全留。 |
| `reasoning` | 留 `id,type,messageID,sessionID,text`；删除其他字段时用 `_mark()` 加 `hasFull:true` 和排序去重后的 `omitted`。 |
| `tool` | `_tool()` 留 ids/tool/callID；state 留 status/title/time；input 仅 `path,filePath,file_path,command,agent,description,subagent_type,todos`；metadata 仅 `sessionId,sessionID,description,agent`；**`output`/`error` 阈值内联**（JSON 字节 ≤4KiB 且 message 累计 ≤16KiB → 留，否则整字段 omit + `hasFull`，绝不半截断）；`structured/result/raw/attachments` 始终删并标记。 |
| `patch` | `_patch()` 留 ids、files 的 path/additions/deletions/status、metadata.path、state status/title/time 及 input 路径键；**`output`/`error` 同 tool 阈值内联**（超 → omit + `hasFull`）。 |
| `file` | `_file()` 留 ids/filename/mime；≤8KiB 的 `http(s)` URL 保留；`data:`、过长或其他 URL 置 null 并标记；source 删除。 |
| `step-start` / `step-finish` | 只留 ids；若删除字段则标记。 |
| `compaction` | orjson 编码≤64KiB 时整 part 保留；超限降为 ids + `hasFull/omitted:["*"]`。 |
| 未知 | 只留 ids；`hasFull:true`，omitted 为实际删除键，若无其他键则为 `["*"]`。 |

转换后若 `_is_renderable()` 判定所有 part 均不可渲染，会**追加**一个 text 占位：`[内容已折叠，点开查看]`，ID 为 `thin_placeholder_{messageID}`，并带 `hasFull:true, omitted:["parts"]`；原 part 不会被丢弃。**rev F**：该 placeholder id **不参与** `/full` 的 `messageId+partId` 对齐；客户端应按 `partId.startsWith("thin_placeholder_")` 做 **message-level 整体替换**。schema-valid 下真实 part `id` 跨 thin/`/full` 稳定。

## 7. B1 实现态补充（G7-soft / G8 / shell deny-list）

### `GET /slimapi/messages/**`（directory 转发）。背景与代码地图见 `docs/ocmar/specs/2026-07-18-v1-b0-b1-design.md`（§2 reality 表 + §3 各项落点）。

### `GET /slimapi/messages/**`（directory 转发）

`/slimapi/messages/{sid}`、`/slimapi/messages/{sid}/full/{mid}` 两条消息路由统一经 `_resolve_messages_directory` 处理 directory。**v0.3.0** allowlist gate 已移除**：directory 不再因 ∉ allowlist 返 400，仅规范化后透传给上游 opencode。复用的 `normalize_directory()` 仍保留以保持转发一致：

| 条件 | 行为 |
|---|---|
| 未传 query `directory` | 不拦（依赖上游默认）；v2 不强制必填 |
| query `directory`（任意值，包括 `/projects` 未列出的） | normalize 后作 `X-Opencode-Directory` 头透传；由上游 opencode 决定能否服务 |
| 同时存在 `X-Opencode-Directory` header 且与 query 冲突 | **400** `{"code":"directory_not_allowed"}`（结构性歧义，slimapi 不猜该透传哪个）。此守卫为 messages 与 token-stream **共用**：messages `/**`（list / full/{mid}）与 `GET /slimapi/sessions/{sid}/stream` 均在 query `directory` 与 header 冲突时返此 400（见 `routes/messages.py::_resolve_messages_directory` 与 `routes/token_stream.py::_resolve_directory_conflict`），无论 directory 下游是否实际消费（token-stream fanout 以 sessionID 为键、directory 是 no-op，但仍校验） |

校验源：`_resolve_messages_directory()`（messages.py）。**directory 合法性 ≠ 多租户隔离**——隔离仍靠 stunnel mTLS（:14097）/ Tailscale ACL + 防火墙（:4097）+ loopback upstream 等网络边界。

### shell/PTY deny-list（catch-all 加固）

`install_proxy(app)` 注册的 catch-all 在转发前对 HTTP 路径做 deny-list 检查；命中即 **403 `{"code":"shell_not_allowed"}`**，不连接 upstream。WebSocket 继续走全局 WS→501（`proxy.py:9-13`），不动。

| 路径模式 | 方法 | 类别 | 来源 |
|---|---|---|---|
| `/session/{sid}/shell` | 任意（method-agnostic） | **任意命令执行**（spawn 子进程） | opencode `groups/session.ts:356`，handler `handlers/session.ts:341-347` |
| `/pty/**` | 任意 | shell/PTY 树（8 条 HTTP 变体：`/pty/shells`、`/pty`、`/pty/{id}` CRUD、`/pty/{id}/connect-token`） | opencode `groups/pty.ts:30-37` |
| `/api/pty/**` | 任意 | v2 PTY 树（7 条同构） | opencode `protocol/src/groups/pty.ts:23-119` |

匹配策略：前缀匹配 `/pty` 与 `/api/pty`；正则 `^/session/[^/]+/shell$` 匹配 `/session/{sid}/shell`。路径表**写死**（来自 B0 全量扫表），不臆造，也不暴露为配置字段。

**间接命令执行入口**（`/session/{id}/prompt`、`/prompt_async`、`/command`、`/tui/execute-command`、`/api/session/{id}/prompt`）**不 deny**——它们是 agent-mediated，且 `prompt_async` 是 §4 透传矩阵的主发送路径。

**Ops 开关**：`OC_SLIMAPI_SHELL_DENY_LIST_ENABLED`（默认 `1`=开）。关闭后 deny-list 不生效，**不构成安全保证**——真实隔离靠 stunnel mTLS + 网络边界 + upstream 权限；deny-list 是 best-effort 第二道。

**已知未覆盖（best-effort）**：路径大小写变体、`/./`、`/../` 段、双重编码。命中策略是精确/前缀字面匹配，不是 URL 规范化防火墙。

> **诚实限制**：catch-all 不识别路径语义是结构性事实；漏路径即可绕过。
