# F-209：catalog 迟到 leader 的 _store 写回已 shutdown 的缓存——"shutdown 清空"不变式可被打破（CD-1 语义下无害）
- 严重度：P3
- 类别：defect（生命周期不变式；无行为影响）
- 位置：src/oc_slimapi/catalog_cache.py:131（`_fetch_and_store` 内 `self._store(key, body)` 无 shutdown 标志）、:173-181（`shutdown` 清 entries + `_sf.shutdown()`）
- 置信度：high
- 快照：0b836e7
- 状态：confirmed
## 证据
- catalog_cache.py:119-133：`_fetch_and_store` 在 factory 内部（singleflight leader 执行）调用 `_store`——`shutdown()` 之后迟到的 leader 完成时仍会写入 `_entries` 并入账 `_retained_bytes`。
- `shutdown()`（:173-181）顺序：`_sf.shutdown()` → `entries.clear()` → `retained_bytes = 0`；SF 层迟到完成有身份复检不再 grace 保留（singleflight.py:503），但 cache 层 `_store` 无对应检查。
- lifespan 侧：`_shutdown_catalog_cache`（app.py:368-375）先于 `_aclose_upstream`（:310-315）执行——leader 的上游 GET 在 shutdown 时仍可能未完成。
- 佐证材料：03-reports/D05-concurrency.md §3 C3；01-explore/parts/e1-07 catalog 卡疑问点 5。
## 分析（机制、影响面、触发条件、可达性）
- 机制：关停窗口内（C6 catalog_cache 清空 ↔ C3 upstream 关闭之间，或清空后 leader 的 factory 尚在飞）迟到的成功刷新把条目写回空缓存。CD-1"shutdown 后保持可用"语义下无行为害处（条目按 TTL 正常过期、无消费方错误）；被打破的是"shutdown 返回后缓存为空"这一测试/运维可观测不变式（`entry_count == 0` 断言可瞬时失败）。
- 触发条件：关停时恰有 in-flight catalog refresh 且其在 entries.clear() 之后完成——窗口毫秒级，lifespan LIFO（upstream 后关）使 leader 大概率在清空前完成。
- 可达性：低；影响限于测试确定性与不变式文档。
## 契约/文档对照（规范轨引文）
- 无 wire 面；模块 docstring :21-22 声明"shutdown() mirrors CD-1 … clears entries"——实现与该句存在迟到写回例外。
