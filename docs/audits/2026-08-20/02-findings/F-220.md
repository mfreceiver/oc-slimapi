## 分析（机制、影响面、触发性）
- 可达路径（窄）：idle 转换时 `_retire_session` 已清一轮（:1062）→ 之后上游**迟到/乱序** text-start 为同 sid 重建 LivePart → 60s 无 delta 且 `_session_status==idle`（:1190-1191）→ 静默退役。此时：
  - v4 客户端 cursor==last_seq（已收到该 part 全部已发帧）重连 → 判 up-to-date 进入 live 模式，挂在一个服务端已无状态的 part 上；该 part 若再有迟到 delta → `live is None` → orphan_deltas++ 静默丢（:782-788）——流静默中断，无 resync 无 barrier 拦截。
  - idle barrier 的 watermark 早于该 part 的帧（idle 时写入）→ cursor 高于水位的重连不被 ④a 拦截，落窗口判定。
- 触发依赖上游事件乱序（正常序列 idle 后无新 text-start），极边缘；与 R4「invalidation 必写 barrier」rationale 相悖的一致性缺口。
