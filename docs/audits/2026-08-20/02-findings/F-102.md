## 证据
- v4-contract §3.2（:67）原文：「v4 视图新增瞬态字段：`auxiliary: {available: bool, mode: "db"|"http"}`（…）；`allowlist: {enabled: bool}`（机制是否启用，B4-4 落地，未配置=false；不泄露清单内容）。」——将 allowlist 与 auxiliary 并列为 **v4 视图新增**。

- 差异确认：真正 v4-only 的新增瞬态字段只有 `auxiliary`（health.py:75-85）；allowlist 在 v3 视图同样存在。
## 分析（机制、影响面、触发条件、可达性）
- 机制：v4-contract §3.2 撰写于 B0（2026-08-17/18）冻结期，将 B4-4（3.3.0）落地物列为「v4 视图新增」；而 B4-4 实际落在 v3 视图的 features 块（3.3.0 先于 4.0.0 发版）。两契约对同一键的「首次出现视图」表述互斥：按 v4 §3.2 读，v3 视图不应有 allowlist；按 v3 §3a 与实现，两视图都有。
- 影响面：纯文档表述——实现行为（两视图均发、不泄露清单内容、ready 不加）与 v3-contract §3a 完全一致，且是加性字段，任何视图的消费方都不受影响。风险是未来以 v4 §3.2 为权威做「v4 视图 diff」的读者/agent 会误判 v3 视图带了多余键，或误把 allowlist 当 v4 gating 依据。
- 可达性：文档读者；无 wire 触发条件。
