## 证据
- plain：`entry.expires_at = self._clock() + self._grace`（:504）→ timer 延迟 = `max(0.0, entry.expires_at - self._clock())`（**注入 clock 差值**）喂 `loop.call_later`（**loop 时钟**调度，:517-519）；到期回调 `_expire_grace_entry` plain 分支复检 `entry.expires_at <= self._clock()`（**注入 clock**，:587）。
- leased：`entry.timer = ... call_later(self._grace, ...)`（:527-529）——完全绕开注入 clock，到期回调不复检时刻只查状态（:590-591）。
- 两个缺口：① 注入 clock 与 loop 时钟**速率/相位**不一致时，plain timer 触发但复检不过 → `_drop` 跳过且 timer 已耗尽 → entry 滞留至同 key 下次 fetch 惰性触发（:568-575）或其他 key churn 逐出；② plain/leased 双口径不一致（同参数注入下行为分叉）。
- 生产判定：默认 `time.monotonic` 与 `loop.time()` 同源（CLOCK_MONOTONIC）——差值口径下 epoch 抵消、速率一致 → **生产正确**；缺口仅在测试注入假 clock（快进/变速）时显形。
- 佐证材料：03-reports/D05-concurrency.md §1 S8；01-explore/parts/e1-07 singleflight 卡疑问点 2。
