# F-276：lifespan 启动日志维护（migrate/compress/prune）同步阻塞事件循环且无超时上限——大积压延迟启动
- 严重度：P3（A9 初判；ops——生产 RETAIN_DAYS=3 下通常亚秒，需积压异常才放大）
- 类别：risk（运维）
- 位置：src/oc_slimapi/app.py:269-280（`migrate_legacy_access_log` / `compress_old_access_logs` / `prune_old_access_logs` 在 lifespan 内直接同步调用，未走 `asyncio.to_thread`）
- 置信度：high
- 快照：0b836e7
- 状态：confirmed
## 证据
- app.py:269-280：三调用为普通函数调用（对照维护循环内同类工作经 `asyncio.to_thread` 分发，src/oc_slimapi/access_log.py:712-724——运行期已正确隔离，仅启动路径未隔离）。
- gzip 工作受 `_MAINT_LOCK` 串行（access_log.py:470）：若上一次进程的维护 to_thread 线程仍在跑（重启竞态），启动路径还会等锁。
## 分析（机制、影响面、触发条件、可达性）
压缩按文件 gzip（老文件可达 MB 级 × 未压缩天数）；异常场景（长期未重启后首启、或手工关闭压缩开关后突然开启、RETAIN_DAYS 调大后历史积压）下启动阻塞秒-十秒级：lifespan 未完成 = 不接请求（uvicorn 在 lifespan 完成前不开始 serving），systemd Type=simple 无独立就绪门，表现为「端口通但请求挂起」。单用户常规部署（每日运行 + RETAIN_DAYS=3）影响亚秒。
