# F-016：Python≥3.11 wait_for(semaphore.acquire()) 取消竞态可能永久泄漏 transform 许可
- 严重度：P3（A5/D05 2026-08-20 复核**降级**：Python 3.14 运行时实证证伪；残留面 = 3.11.x 部署）
- 类别：risk
- 位置：src/oc_slimapi/transform.py:238-241（`await asyncio.wait_for(self._semaphore.acquire(), timeout=wait_seconds)`）
- 置信度：high（实证 + CPython 源码对照）
- 快照：0b836e7
- 状态：confirmed
## 证据
- 代码：transform.py:236-246（acquire → wait_for → TimeoutError→TransformBusy → `_active += 1`）。
- **运行时事实**：本机 `.venv/bin/python` = 3.14.4；pyproject.toml:9 `requires-python = ">=3.11"`。
- **实证（独立脚本，/tmp stdin，零仓库写入，2026-08-20）**：
  - 竞态 A（release 与 timeout 同瞬）：20,000 次迭代，每次后 `Semaphore._value == 1`——**零许可泄漏**；
  - 竞态 B（parked waiter 外部取消 + holder 释放）：10,000 次迭代——**零泄漏**。
- **CPython 3.14 源码对照**（`asyncio.locks.Semaphore.acquire`）：`except CancelledError: if fut.done() and not fut.cancelled(): self._value += 1`（唤醒竞态下许可**归还计数器**而非丢失）+ 尾部 `while self._value > 0: _wake_up_next()`（FIFO 补醒）。`asyncio.wait_for` 自 3.12 起为 `asyncio.timeout` 薄包装——≤3.11 旧实现（bpo-42130 族"完成/取消边界丢结果"竞态）才是本 finding 描述的暴露面。
- `_active` 计数安全：`wait_for` 成功返回与 `self._active += 1`（transform.py:246）之间无 await → 取消不可投递于其间（asyncio 取消仅在挂起点投递）。
- 佐证材料：01-explore/parts/e1-07 疑问点 1；03-reports/D05-concurrency.md §2 T6 + §8。
## 分析（机制、影响面、触发条件、可达性）
- 机制（原假设）：任务在 `semaphore.acquire()` 即将完成的同一瞬间被取消/超时 → 许可已扣但调用方收到 TimeoutError/CancelledError → 永不 release → 池容量永久 -1。
- 3.12+（含 3.14，本仓实际运行时）：`Semaphore.acquire` 的取消补偿 + `wait_for` 新实现使该竞态**不存在**——许可要么正常返回（调用方照常 release），要么归还计数器并补醒后继。
- 残留面：`requires-python = ">=3.11"` 名义支持 3.11.x——3.11 的旧 `wait_for` 实现仍带丢结果竞态。若生产/测试环境固定在 3.12+（当前 .venv=3.14.4），实际暴露为零。
- 可达性：3.14 部署 = 不可达；3.11 部署 = 请求恰在 admission 排队获得许可瞬间断连时触发（原 e1-07 评估）。
## 契约/文档对照（规范轨引文）
- 无 wire 面（池内部许可纪律）；`TransformBusy`→503 形状不受影响。
