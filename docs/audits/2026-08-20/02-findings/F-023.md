## 证据
- src/oc_slimapi/middleware/traffic_accounting.py:162-165：`if scope.get("type") != "http": await self.app(...)` —— WebSocket scope 原样直通，无 receive/send 包装、无 access 行（proxy.py:34-38 的 501 stub 帧字节零记账）。
- 500 字节绕过链：Starlette build_middleware_stack = `[ServerErrorMiddleware] + user_middleware + [ExceptionMiddleware]`（starlette/applications.py:69-71）——ServerErrorMiddleware 在 RequestId/TrafficAccounting/Selector（app.py:747-755 user middleware）**之外**。路由内未捕获异常 → TrafficAccounting 在 `except BaseException` 分支记账（status=500、down_out=已过 counted_send 的部分，traffic_accounting.py:214-233）→ re-raise → ServerErrorMiddleware 渲染 500 响应体——该响应的 send() 不再经过 counted_send ⇒ **downOut 恒漏记 500 实体字节**。
- 对照：CodedHTTPException/ExceptionMiddleware 处理的错误（编码错误体）在 user middleware 之内渲染，字节正常计数——盲区仅限「逃逸到 ServerErrorMiddleware 的未分类异常」。
- 【A8 关联】F-253（路径参数控制字符→httpx InvalidURL→裸 500）与 F-013（超长 LEI seq→ValueError 500）产生的正是这类 500——每次触发的响应字节均不入账。
## 分析（机制、影响面、触发条件、可达性）
- 机制：中间件拓扑使最外层错误渲染器绕过计数包装；WS 分支按类型直通（设计上认为非 http 即 lifespan——WS 是遗漏的类型）。
- 影响面：①WS 501 stub（若客户端尝试 upgrade）零观测；②未分类 500 的 downOut 低估（access 行 status=500 仍在——**有行无字节**，非完全盲）。
- 触发条件：①任意 WebSocket upgrade 尝试（proxy.py:34-38）；②任意逃逸异常（现状已知触发器：F-013、F-253）。
- 可达性：三入口恒可达；纯观测缺口，无资源/安全后果放大。
