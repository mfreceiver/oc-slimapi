## 分析（机制、影响面、触发条件、可达性）
- 机制：v4 将 sessions 列表重构为全局 DB 投影面（dbaux 单 SQL 组装），directory 作为过滤维度被整体移出参数域（selector 层前置拦截，先于路由）。
- 影响面（对多工作目录客户端）：
  1. **per-workdir 会话列表退化为客户端过滤**：须全局拉取（或按 cursor 翻页）后按 `item.directory` 过滤；目标 workdir 会话稀疏时 cursor 在全局序上推进需遍历多页无关行——无服务端效率等价物。
  2. **per-directory `complete` 不可判定**：v4 `complete` 仅表全局分页窗口完备（§4.1 LIMIT+1 窗口判定）；「该目录列表已完备」的 v3 语义无对应。
  3. **无 directory 检索轴**：search 仅 title 字面子串；§17 将 cross-session search 定为永久 non-goal——缺口无未来服务端补齐路径（再启用须推翻正式修订）。
  4. 缓解面：`/slimapi/directories` 发现保留（§4.6 不升 DB 投影、形态不变）；allowlist 非空时全局列表有子树谓词（仅收紧不扩展）。
- 触发条件：ocdroid（或任何多 workdir 客户端）执行 v3→v4 迁移（B5a/B5b）时必然触达。
- 可达性：当前零影响（ocdroid 锁 v3、v3 面不变）；为迁移评估期发现，非生产行为缺陷。
