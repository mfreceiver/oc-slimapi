## 分析（机制、影响面、触发条件、可达性）
- 机制：`_fail_closed_503` 是 sessions.py 私有统一出口，§13 修订新增的单查族（read_groups.py）与列表 fallback 的 worker 内 raise 都绕开了它；worker 线程无 request 引用使「补写」不能简单复用现有函数。
- 影响面：这些 503 在 access log 无 `degraded503:true` 稀疏字段、ledger 无 `degraded|fail_closed|…` 矩阵键、`metrics.sessionsDegraded.fail_closed_503` 漏计——运维看到的降级率被低估（单查族整体是盲区；列表仅在 fallback+不可表示项的组合下漏计，该组合本身罕见）。
- 触发条件：反例 1 = dbaux 不可用 + Class A 降级 200 路径中存在不可表示 item（改为 503）；反例 2 = v4 单查的四种失败（dbaux sqlite 错/坏行/不可表示 ×2）。
- 可达性：单查族 503 在 dbaux 异常态常态可达；反例 1 罕见（先决条件链长）。
