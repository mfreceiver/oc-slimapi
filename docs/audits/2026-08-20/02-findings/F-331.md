# F-331：观测面无错误码维度——503/502/413 族内部多码不可区分，且 200 载部分失败完全不可见
- 严重度：P3（观测归因缺口，非行为错误；排障成本项）
- 类别：gap（observability）
- 位置：src/oc_slimapi/traffic.py:576-611（矩阵只到 statusClass）；src/oc_slimapi/access_log.py:333-364（行无 code 字段）；src/oc_slimapi/routes/questions.py / permissions.py（envelope errors[]/truncated）
- 置信度：high
- 快照：0b836e7
- 状态：confirmed
## 证据
- traffic.py:576-580 `_v3_status_class` 只输出 "Nxx"；:582-611 `record_selector_request` 矩阵键第 5 段=statusClass——503 族（upstream_unavailable / transform_busy / auxiliary_unavailable / action_unavailable）、502 族（upstream_http_N / upstream_invalid_shape / provider_upstream_malformed）、413 族（request_too_large / response_too_large / message_too_large / provider_projection_limit / expand 族 413）各自内部不可区分。**E2 census 的 `upstream_http_<N>` 无独立计数**（rg 全仓无 per-code 计数器）。
- access_log.py:333-364：write_access_log 字段集无 `code`——access log 行也无法区分同状态多码。
- questions/permissions：per-dir 失败进 envelope `errors[]`、预算截断进 `truncated:true` 时 HTTP 仍 200——ledger 记 2xx、矩阵记 "2xx"，**部分目录失败在全部观测面不可见**（响应体是唯一载体）。
## 分析
- 机制：观测链（ledger + access log + 矩阵）以 HTTP 状态为最高失败分辨率；sidecar 自有错误码体系（v3 §8/v4 §8.1 的 ~30 码）从未投影进任何观测位。
- 影响面：D13 §1.2 覆盖表 54 路由中码级归因 0 条可达；「为什么 503」必须靠响应体重放或 journald 交叉；questions/permissions 的多目录部分失败（最常见的降级形态）零观测。
- 触发条件：任意失败归因查询。
