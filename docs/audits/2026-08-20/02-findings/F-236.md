# F-236：stop() 的 close submit 无界等待——在途查询可把关停拖出 drain 预算
- 严重度：P3
- 类别：defect
- 位置：src/oc_slimapi/dbaux/lifecycle.py:399（`await self._submit(self._close_conn)` 无超时）
- 置信度：high（代码逐行，快照 0b836e7）
- 快照：0b836e7

## 证据
- lifecycle.py:383-405 `stop(drain_seconds=5.0)` 四段中，仅 :391（周期任务 `wait_for(task, timeout=drain_seconds)`）与 :402→:407-423（executor 有界 drain）受预算约束；**夹在中间的 :399 close 提交无任何超时**：
  ```python
  try:
      await self._submit(self._close_conn)   # :399 —— FIFO 排队在途查询之后
  ```
- close 进同一单 worker FIFO → 等待在途 `_run_query` 完成：最坏 = busy_timeout 5s（lifecycle.py:302,:510 锁等待）+ fetchall 大结果集物化时间（无上界）。
- app.py:85 `_DBAUX_DRAIN_TIMEOUT = 5.0` / app.py:605-615 `_stop_dbaux` 调 `stop(drain_seconds=...)`——drain_seconds 不覆盖该段。
- `_bounded_executor_shutdown` 的「超时也返回」承诺（:409 docstring）只覆盖其自身阶段。
## 分析
- 影响：关停链（LIFO，见 F-010：最坏 30+5+10s 级 vs systemd TimeoutStopSec=15）中 dbaux 段可超预算 → SIGKILL 截断后续清理（snapshotter 终帧/access-log flush）风险叠加。
- 触发：关停瞬间恰有慢投影查询在 worker 内（大 limit/大库/busy）。
- 缓解现状：watcher 为 daemon 线程（:419-422），进程退出不被阻塞；阻塞的是事件循环内的 stop await。
