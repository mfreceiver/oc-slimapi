# F-342：clientId 隐私口径双弱点——无 salt 的 sha256 跨部署可链接 + `CLIENT_ID_HASH=false` 明文回退零告警零 ops 记载
- 严重度：P3（单部署设备数量级下碰撞/链接风险低；隐私合规与运维 unaware 面）
- 类别：risk（privacy/observability）
- 位置：src/oc_slimapi/access_log.py:92-103（hash_client_id）；src/oc_slimapi/middleware/traffic_accounting.py:305-317（明文分支）；docs/operations.md（零记载）；docs/manual/traffic-accounting.md:168,258-259
- 置信度：high
- 快照：0b836e7
- 状态：confirmed
## 证据
- access_log.py:92-103：`hash_client_id(raw, salt=None)` 无 salt 时 `sha256(raw)[:16]`——**无密钥哈希**：任何持有同 raw（设备 id 通常稳定且低熵）者可预计算匹配，跨部署/跨实例可链接；salt 设置时才 hmac_sha256。
- traffic_accounting.py:310-317：`client_id_hash` 默认 True（fail-closed 正确）；false 时**明文 device id 入日志**，无任何 warning/启动 banner 提示隐私回退发生（布尔旋钮静默 False 家族，config-census §7.4）。
- 文档：手册 :168/:258-259 记载了 hash 机制与 salt env，但 operations.md **零记载**两旋钮（config-census D10）——生产未配 salt 也无推荐（默认 None）。
## 分析
- 机制：默认形态（hash=True、salt=None）= 可链接伪匿名；opt-out 形态 = 明文。两者都无运行时信号。
- 影响面：单用户家庭部署（受威胁模型 D08 限定）实际风险低；但日志文件若外发分析（手册 §5 鼓励 jq 离线分析、导出 `> oc-slimapi-today.log`），clientId 明文/可链接值随之扩散。
- 触发条件：默认即第一种形态；第二种需显式 opt-out。

- v2-contract §7（client header 可观测性，历史）未规定 hash 强度；traffic-accounting.md 记载机制但无隐私建议（配 salt 与否的 trade-off 未述）。
