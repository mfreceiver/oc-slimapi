# F-021：/full/{mid} 上游 404 误映射为 session_not_found（携带 sessionID）——消息缺失与会话缺失语义混淆
- 严重度：P3（初判，按 §3.3 决策表待 Phase 2/3 复核定级）
- 类别：defect
- 位置：src/oc_slimapi/upstream_errors.py:80-81（映射点）；入口链 src/oc_slimapi/routes/messages.py:507-511（/full）、:796-801（列表）、:1017-1022（merged fulls）经 `_catalog_common.read_upstream_response`（:136）→ `raise_upstream_status_code(status, sid=sid)`
- 置信度：high（A10 证据链填充后）
- 快照：0b836e7
- 状态：refuted
## 证据
- 映射实现（upstream_errors.py:80-81）：
  ```python
  if status == 404 and sid is not None:
      raise CodedHTTPException(404, code="session_not_found", sessionID=sid)
  ```
  —— 任何带 sid 的上游 404 一律 `session_not_found`。
- messages 三入口均传 `sid=sid` 调 `read_upstream_response`（messages.py:507-511、:796-801、:1017-1022 → _catalog_common.py:136）→ 上述映射点；`/full/{mid}` 的「消息不存在」上游 404 因此同样映射为 `session_not_found`。
- 上游真值（E8 定论，01-explore/upstream-notes.md:54；快照 v1.18.18 源）：`session.get` 404 → `SessionNotFoundError{sessionID}`（session.ts:91-105）而 `session.message`（单消息 GET）404 → **`MessageNotFoundError`**（session.ts:373-383）——上游本身区分会话级/消息级缺失。
- 佐证材料：01-explore/parts/e1-02-messages.md 疑问点 2、映射表 :196 行。
## 分析（机制、影响面、触发条件、可达性）
- 机制：`sid` 参数双义（会话存在性判定 vs 仅路由作用域标记）——`raise_upstream_status_code` 的 404+sid 语义在 session-scoped 路由上把「消息缺失」误标为「会话缺失」。列表路由（`/session/{sid}/message` 无 mid）该映射正确；`/full/{mid}`（与 merged fulls 内单条 full）该映射错误归因。
- 影响面：客户端删除/过期单条消息后拉 full → 收 `session_not_found{sessionID}` → 可能误判整会话消失触发冷同步/丢弃本地会话态（恢复动作过重但可自愈）。
- 触发条件：mid 不存在/已删（fork 后 revert 等场景真实可达）；可达性=每 full 请求按 mid 命中率。
## 契约/文档对照（规范轨引文）
- v3-contract :197「session_not_found（sid 404）」复用码——契约未区分 message 级缺失；若引入 message_not_found 需加性变更（minor 发版 + CHANGELOG）。
