## 分析（机制、影响面、触发条件、可达性）
- 机制：脚本信任 pyproject version 为唯一真值源做增量 bump，但对「真值源自身被人工改坏」零防御；CHANGELOG 门禁只看新版本节标题存在性。
- 触发条件：人工回拨/跳改 pyproject 版本、忘折叠 [Unreleased]、写错日期格式——均人工失误类。
- 影响面：撞 tag/跳号在 F-361 窗口才暴露（半发版态）；[Unreleased] 残留导致下版 CHANGELOG 内容漏发（ocdroid 对接信息缺失）；日期错乱影响 changelog 可读性。均不破坏已发布产物。
## 契约/文档对照（规范轨引文）
- docs/release.md §6「禁止跳过版本号（如 0.1.0 → 0.1.2）除非用户明确要求」「禁止复用已 push 的 tag」「禁止拆开发版状态」——三项禁令均无机械 enforcement，纯流程纪律。
- release.md §3.3.5「打开新的 ## [Unreleased] 空节（若 release 脚本未自动加）」——脚本确不自动加，依赖人工。
