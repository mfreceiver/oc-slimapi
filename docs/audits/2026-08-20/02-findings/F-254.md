# F-254：%3F 路径参数解码后经 f-string 进上游 URL → httpx 以 `?` 为分隔符 → 上游 query 注入（含 directory/workspace 注入语义；实际影响被上游优先级对冲）
- 严重度：P3
- 类别：security（参数注入，低实效）
- 位置：同 F-253 的插值族（_read_passthrough.py:103-116 `_raw_upstream_url` 拼接 + _catalog_common.py:79 build）；上游语义佐证 `opencode-src/current/packages/opencode/src/server/routes/instance/httpapi/middleware/workspace-routing.ts:86-88`
- 置信度：high（httpx 库级实测）；实效评估 medium（对冲链依赖上游 v1.18.18 行为）
- 快照：0b836e7
- 状态：confirmed
## 证据
- httpx 0.28.1 实测：`build_request("GET", "/session/x?limit=0")` → raw_path `/session/x?limit=0`——插值进路径的解码 `?` 被 URL 解析为 query 起始，**不重编码**；`#` 同理截为 fragment 后丢弃。
- 入口链：`GET /slimapi/session/x%3Fdirectory=%2Fetc?v=3` → uvicorn 解码 path=`/slimapi/session/x?directory=/etc` → `{sid}`=`x?directory=/etc` → 上游 URL=`/session/x?directory=/etc`。
- 上游 query 优先级语义（佐证）：workspace-routing.ts:86-88 `defaultDirectory = url.searchParams.get("directory") || request.headers["x-opencode-directory"] || process.cwd()`——**query directory 压过 sidecar 转发的 header**；`?workspace=` 可触发 resolveWorkspace → 存在的 remote workspace 会走 proxyRemote（:113-146，上游自身代理面）。
- 对冲事实：session 形路径先取会话自身 directory（workspace-routing.ts:182 `session?.directory || defaultDirectory(...)`）——sid 真实存在时注入的 directory 不生效；sid 不存在时请求 404（session_not_found），注入仅改变 404 的解析路径。非 session 形上游路径无客户端插值。
## 分析（机制、影响面、触发条件、可达性）
- 机制：路径参数经一次解码后未按「路径段」语义重编码即拼入 URL。
- 影响面（现实）：上游 4xx/5xx 形状扰动（如注入 workspace=不存在 → 上游 500 "Workspace not found"）；理论面：绕过 sidecar 的 directory 消费（selector 剥 query directory 的意图）向上游注入 directory/workspace——但被 session-directory 优先级与 404 短路对冲至接近零。clients 也可用 `%23` 截断自身请求（自伤）。
- 触发条件：插值段含 `%3F`（或 `%23`）。
- 可达性：三入口恒可达；**无放大后果**。
