# F-027：dbaux allowlist 谓词不 strip 而 cursor 指纹 strip——同 directory 不同指纹组合可产生 400/false-accept
- 严重度：P3（Phase 2 A7 复核维持；触发面 = 运维误配置，失效方向 fail-closed）
- 类别：defect
- 位置：src/oc_slimapi/dbaux/projection.py:200-215（SQL 谓词原样项）+ src/oc_slimapi/dbaux/cursor.py:109-113（指纹 strip）+ src/oc_slimapi/routes/sessions.py:365-368（入口同样不 strip）
- 置信度：high（双轨代码 + 测试锚点复核，快照 0b836e7）
- 快照：0b836e7
- 状态：confirmed
## 证据
- 指纹侧（规范化）：cursor.py:109 `normalized = {e.strip() for e in (entries or ()) if e and e.strip()}` → sorted → canonical JSON → sha256[:16]。
- SQL 侧（不规范化）：projection.py:200-215 `items = tuple(allowlist)`，仅拒绝非 str/空串（:204-208），项内容**原样**绑定 `:214 params.extend((item, len(item) + 1, item + "/"))`。
- 入口侧（不规范化）：sessions.py:365-368 `tuple(entry for entry in configured if entry)`——只滤 falsy，不 strip。
- 测试锚定（有意行为）：tests/test_cursor_matrix.py:299-304 `assert _fp(allowlist=("/a ", " /b", "")) == _fp(allowlist=("/b", "/a"))`——指纹 strip 归一化是冻结测试语义；SQL 侧无对应归一化。
## 分析（机制、影响面、触发条件、可达性）
- 机制：指纹比 SQL 谓词**粗**（strip+去重 vs 原样）。配置 `"/a "`（尾空白）与 `"/a"` 同指纹，但 SQL 分别绑 `"/a "`/`"/a /"` 与 `"/a"`/`"/a/"`——前者匹配不到任何 directory 行（空目录也不含尾空白路径）。
- 后果（均为单向）：
  1. **stale-cursor false-accept**：运维修正 `"/a "` → `"/a"` 时指纹不变 → 旧 cursor 继续通过校验（不 400），但结果集已变（空 → 有行）——翻页跨配置变更的漏检面；
  2. 含尾空白配置静默零结果（白名单过滤方向 fail-closed，不泄行、不误放）。
- 「400 false-positive」不成立的推导：不同指纹 ⟺ strip 后集合不同 ⟹ SQL 项集也不同 → 指纹拒绝与谓词差异一致，400 正确。
- 触发条件：`directory_allowlist` 配置含首尾空白项（误配置）；可达性 = 配置面，非客户端输入面。
