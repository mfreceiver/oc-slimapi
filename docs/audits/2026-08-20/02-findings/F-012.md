## 证据
- lifecycle.py:505 `path = self._resolution.path  # type: ignore[union-attr]`——`DisabledResolution`（path_resolution.py:51-59）只有 `reason`/`detail` 两字段，无 `path` 属性 → worker 内 `AttributeError`。
- 触发链（逐行）：tick :616-6717 `if self._state == "disabled" and self._reprobe_allowed: await self.reprobe()` → reprobe :652-657（`_reprobe_allowed` 为 True——:349-352 仅排除 `explicit-memory`/`upstream-memory`，**不排除** `not_found`/`path_ambiguous`）→ `_open_and_gate` :549-551 → `_open_and_gate_sync` :521-530 → `_open_conn` :505 AttributeError。
- 归宿：:552 `except Exception as exc` 捕获 → `reason = "gate_failed" if "schema gate" in str(exc) else "open_failed"`——`str(AttributeError)` = "'DisabledResolution' object has no attribute 'path'"，不含 "schema gate" → reason 漂移为 **open_failed**；:556-558 每 30s warning 一次。
- 不可自愈根因：`resolve_db_path()` 全仓唯一调用点 = app.py:598（启动一次性），进程内不重跑候选发现；两类 reason 的重探**必然**重复失败。
- 负向证据：`rg "resolve_db_path" src/` 仅 app.py:22（import）+ app.py:598；测试 tests/test_dbaux_lifecycle.py:267-283 只覆盖 `explicit-memory` 的 reprobe=False，not_found/path_ambiguous 重探分支零覆盖。
## 分析（机制、影响面、触发条件、可达性）
- 机制：状态机对 `disabled(not_found|path_ambiguous)` 定义了 `reprobe` 转移，但 reprobe 实现假设 resolution 携带 path——Disabled 分支无此数据，属未定义转移的实现层崩溃（被 catch-all 吞掉转化为 reason 漂移）。
- 影响：(1) health `auxiliary.reason` 与 metrics `dbaux.reason` 从 `not_found`/`path_ambiguous`（真实诊断：装库缺失/多候选）漂移为 `open_failed`（假象：临时打不开，看似可自愈）——运维误判；(2) 每 30s 一次 warning 日志噪声 + probes 计数虚增；(3) 「冷启动竞态自愈」注释（lifecycle.py:615）对这两类 reason 不成立——上游后来装好库也不会被Sidecar发现（需重启 sidecar）。
- 可达性：生产常态可达——`not_found`（XDG 目录无 `opencode*.db`，上游未装/未启动过）或 `path_ambiguous`（多候选）任一出现即进入 30s 循环。
- 功能面：无——fail-closed 降级 HTTP 正确，wire 行为符合 §4.2。
