# F-013：Last-Event-ID 超长 seq 数字串（>4300 位）int() 抛 ValueError 未捕获 → 500（非 400）
- 严重度：P3（A6 终判：P2→P3 降级——可达性证实但触发面受限，见分析）
- 类别：defect
- 位置：src/oc_slimapi/sse/replay_wire.py:83（`_SEQ_RE`）+ :166（`int(seq_text)`）
- 置信度：high（A6 实证）
- 快照：0b836e7
- 状态：confirmed
## 证据
- replay_wire.py:83 `_SEQ_RE = re.compile(r"^[0-9]+$")`——纯数字**不限长度**；
- replay_wire.py:164-166：`if _EPOCH_RE.match(epoch) is None or _SEQ_RE.match(seq_text) is None: return None` 后 `return epoch, int(seq_text)`——**int() 无 try**；
- 调用链负向搜索：`classify_reconnect`（:169-209）无 ValueError 分支；路由 events.py:115-118 / token_stream.py:154-158 直接调用亦无——异常透传 FastAPI → 500；
- 实测（审计 venv，Python 3.14.4）：`int("9"*5000)` → `ValueError: Exceeds the limit (4300 digits) for integer string conversion`；`sys.get_int_max_str_digits() == 4300`（Python ≥3.11 默认）；
- 头部可达性：h11/uvicorn 请求头上限 64KiB >> 4300 位 seq + `Last-Event-ID: g:<16hex>:` 前缀——请求可完整送达。
## 分析（机制、影响面、触发条件、可达性）
- 机制：语法合法（十进制）但资源超限的 seq 使 `int()` 抛 ValueError → 5xx。契约 §7.2 ① 冻结「格式非法 → 忽略 + 重置（首连语义）」——任何客户端可控的 Last-Event-ID 值都不应产生服务端错误。
- 触发面：仅恶意/损坏客户端手工构造 >4300 位 seq；部署面 = loopback + stunnel mTLS 之后（已认证消费方 ocdroid）。影响 = 单请求 500 + 错误日志噪音，无状态腐蚀、无放大（每次请求独立）。
- 定级理由：初判 P2 假设了开放暴露面；A6 核实部署拓扑（mTLS 后）与影响（单请求 500）后降 P3。
