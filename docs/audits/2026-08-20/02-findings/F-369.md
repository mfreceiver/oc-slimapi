## 证据
- pyproject.toml:9 `requires-python = ">=3.11"` 无上界——宣称兼容 3.11 至无穷；:2 build 依赖 `setuptools>=75` 同样无上界（构建行为随 setuptools 大版本漂）。

## 分析（机制、影响面、触发条件、可达性）
- 机制：Python 无上界声明 = 未来的每个新 Python 版本都被「宣称」支持，而实际只在 3.14（现）验证过；依赖栈（pytest-asyncio）的弃用周期不受本仓控制。
- 触发：升级系统 Python 重建 venv（3.16+）时测试栈断；或 pip 在新解释器上按 metadata 认为兼容而装出坏环境。
- 影响面：门禁（check.sh）整体失效风险——比运行时更早显现（生产锁 3.14 venv 不动则不触发）。
