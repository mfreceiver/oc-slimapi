## 分析（机制、影响面、触发条件、可达性）
- 【A3 补】可达性：任何持 stunnel 凭据的消费方 `GET /slimapi/config/providers?v=3` 即获明文 provider api/key；v=4 投影面已脱敏（providers_projection.py + 指纹 providers-projection-v2）。风险敞口 = v3 窗口存续期（至 5.0.0 收敛 (4,4)）× v3 面消费方集合。
- 【A8 分层定级】：
  - **E-I（loopback）/E-III（stunnel mTLS）= P2**：认证已由 stunnel 完成，消费方=持证书客户端——但「证书受众=密钥面受众」：stunnel CA 签发的每张客户端证书的持有者都可读取全部 provider key；密钥经 sidecar 中转扩大可取面（无需直连 opencode :4096/:14096）。单用户自部署下消费方集合可控 ⇒ P2。
  - **E-II（0.0.0.0 明文）= HIGH（P1 级）**：与 F-251 同前置——免认证 `GET /slimapi/config/providers?v=3` 直接吐出 provider api/key；deploy 边界（Tailscale ACL）不可实机验证 ⇒ 标「部署边界未验证」。
- 【A8 补】信息不对称注记：v4 投影面同 URL 存在意味着泄露是**版本协商可选项**——攻击者/旧客户端只需选 `?v=3`；脱敏与否不依赖服务端配置而依赖客户端自报版本。
