# F-205：access-log DailyAccessHandler.emit 每请求同步 write+flush 在事件循环上（含跨午夜 rollover 的 close/open）

- 类别：risk（事件循环上的同步文件 IO；设计自称 best-effort）
- 位置：src/oc_slimapi/access_log.py:172-199（write :195）；调用链 src/oc_slimapi/middleware/traffic_accounting.py:319（`write_access_log`，每请求/SSE 生命周期）
- 置信度：high
- 快照：0b836e7
- 状态：confirmed
## 证据
- access_log.py:188-198（emit）：日期变更时 `_close_current_fh()` + `_ensure_dir()` + `_open_file(today)`（open/close 同步 syscalls），随后 `self._current_fh.write(msg + "\n")` + `self.flush()`——logging.Handler 同步协议，调用方在事件循环线程。
- traffic_accounting.py:319 经 `write_access_log` → `logger.info(json.dumps(record...))`（access_log.py:408）——每 HTTP 请求一行 + SSE open/close 生命周期行。
- 对照：维护路径（compress/prune）已 `asyncio.to_thread`（access_log.py:712-724）——同文件对重 IO 有 offload 纪律，唯独 per-line emit 例外。
- 佐证材料：03-reports/D05-concurrency.md §6.2 N5。
## 分析（机制、影响面、触发条件、可达性）
- 机制：每请求一次同步 write+flush（flush=write(2) 到 page cache，非 fsync——注释 :195 自明"非 fsync/事务"）。正常本地盘为微秒~亚毫秒级；**磁盘慢速/满/网络文件系统**（access_log_dir 可配置）时每次 flush 可达毫秒级以上并串行化所有请求的尾延迟；跨午夜首请求额外承担 open+close。
- 设计权衡已注释（best-effort、单调用行写入缩小半行窗口），但 QueueHandler/QueueListener 是 logging 标准异步模式，可同时保住单调用写入语义与 loop 解耦。
- 触发条件：`access_log_enabled=true`（生产默认开，AGENTS.md 述生产落 StateDirectory）下的每个请求。
