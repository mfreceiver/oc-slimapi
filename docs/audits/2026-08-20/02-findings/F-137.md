## 证据
- app.py:734：`app = FastAPI(title="oc-slimapi", version=__version__, lifespan=lifespan)`——未禁用默认文档路由。
- 只读 introspection（import app 枚举 routes）：4 条非 `/slimapi`、非 catch-all 路由在挂：`({GET,HEAD}, /openapi.json)`、`({GET,HEAD}, /docs)`、`({GET,HEAD}, /docs/oauth2-redirect)`、`({GET,HEAD}, /redoc)`——FastAPI `__init__` 期注册，先于 install_proxy 的 catch-all（app.py:762）故命中优先。
- traffic.py:191-192：非 `/slimapi/` 前缀 → `"passthrough"` 桶——这 4 条路由的 200 响应将记入 passthrough（requests/200、downOut）。
- tests/test_proxy.py:76-84 的退役路径参数表未含 docs 路径——现有测试未覆盖此穿透。
## 分析（机制、影响面、触发条件、可达性）
- 机制：FastAPI 默认装配面与「v3-only 终态：一切 HTTP 面 = 收编路由或 404」的 §8.2 声明冲突——4 条框架自带路由构成第三种状态（未收编但 200）。
- 影响面：① 破坏 passthrough 桶哨兵性质（dataflows 场景 10：「一旦该桶出现 200，即有路径意外穿透」——现在恒有 4 条合法穿透源，监控该哨兵即误报或被迫忽略）；② `/openapi.json` 向任何能到达 sidecar 的消费方暴露全 API schema（/slimapi 全路由 + 模型形状）——面在 stunnel mTLS + loopback 之后，实际暴露受边界保护，但属未列契约/INTERFACE_MAP 的计划外面；③ `/docs/oauth2-redirect` 完全无意义。
- 触发条件：GET/HEAD 这 4 条路径即触发；匿名消费方/扫描器可达（经 stunnel 认证后）。
- 可达性：恒可达。
## 契约/文档对照（规范轨引文）
- v3-contract §8.2-3.0.0：「catch-all **关闭**。未收编路径 → 404 `{"code":"thin_route_not_found"}`」——docs 路径是「未收编路径」但非 404，与契约字面冲突（契约显然未预期框架自带面）。
- route-census.md 双计数声明 54 路由全集——docs 四路由在 census/inventory/INTERFACE_MAP 均无记录。
