## 3. B1 交付项

### 3.1 G2 — `GET /slimapi/sessions/{sid}/status` 错误语义分离

**落点**：`src/oc_slimapi/routes/sessions.py:121-149`（`session_status()`），两个 `try/except Exception→503` 段。

**目标语义表**（spec §3）：

| 条件 | HTTP | body |
|---|---|---|
| upstream 404 / 明确 not found | **404** | `{"code":"session_not_found","sessionID":"…"}` |
| discover 得到的 directory ∉ allowlist | **400** | `{"code":"directory_not_allowed"}` |
| upstream 其它 4xx（401/403/409 等） | **502** | `{"code":"upstream_http_N"}` |
| upstream 超时 / 5xx / JSON 坏 | **503** | `{"code":"upstream_unavailable"}` |
| 成功但 map 无 sid | **200** | `{"type":"idle"}`（假 idle 风险：session 已删但 status map 滞后可能误报 idle，仅文档注明） |

**实现要点**：
- `require_directory()` 抛的 `HTTPException`（allowlist 400 / refresh 503）必须 **re-raise**，不得被 `except Exception` 吞。
- 对 upstream 用 `httpx.HTTPStatusError` 精确判 404（catch 后看 `exc.response.status_code`）；其它 4xx → 502 `upstream_http_N`；仅网络异常/5xx/`.json()` 解析失败 → 503 `upstream_unavailable`。
- 批量 `GET /slimapi/sessions/status`（`sessions.py:107-118`）语义不变（现状透传 upstream status）。

### 3.2 G8 — `GET /slimapi/messages/{sid}/full/{mid}` 流式 cap

**落点**：`src/oc_slimapi/routes/messages.py:419-435`（full-mode 分支）。

**目标**：
- full-mode 改为 **stream**：`client.send(req, stream=True)` → `read_with_cap(response, config.max_message_bytes)` → 累计超限立即中止 + `413 {"code":"message_too_large","limitBytes":…}`。
- **禁止**"先完整下载再查 32MiB"（现状 `len(response.content) > max_message_bytes`）。
- 超限/异常后须 `try/finally: await response.aclose()`（防连接泄漏；复用 `messages.py:280-281` 模式）。
- 参数不变（`mode`、`directory`、`sid`、`mid`）。
- **transform-busy 归一**：代码层已就绪（`_busy_response` 返 503），本 run 仅更新 `docs/INTERFACE_MAP.md` line 23 文字（§4）。

### 3.3 G7-soft — messages directory allowlist

**落点**：`src/oc_slimapi/routes/messages.py` 三 handler（list `:336-408` / since `:198-333` / full/{mid} `:411-465`）。

**目标语义**（spec §5）：

| 条件 | 行为 |
|---|---|
| 未传 query `directory` | 不拦（依赖上游默认）；**v1 不强制必填** |
| 传了 query `directory` 且 ∈ allowlist | 通过 |
| 传了 query `directory` 且 ∉ allowlist | **400** `{"code":"directory_not_allowed"}`；允许 miss 时刷新 projects 一次 |
| 同时存在 `X-Opencode-Directory` header 且与 query 冲突 | **400** `{"code":"directory_not_allowed"}` |

**实现要点**：
- 复用 `require_directory(request, directory)`（`sessions.py:53-62`），不新建 helper。
- **新加** query/header 冲突检测：三 handler 入口检查 `request.headers.get("x-opencode-directory")` 与 query `directory` 不一致 → 400。
- **禁止**宣称 soft = 多租户隔离；隔离靠 stunnel/mTLS + 网络边界。

### 3.4 shell deny-list

**落点**：`src/oc_slimapi/proxy.py:17` 之后（HTTP catch-all 入口）+ `src/oc_slimapi/config.py:55` 之后（新字段）。

**目标**：
- 默认配置 deny-list **默认开启**（`OC_SLIMAPI_SHELL_DENY_LIST_ENABLED=1`）。
- 命中 §1.3 路径表 → **403** `{"code":"shell_not_allowed"}`。
- 提供 ops 配置项可关闭（关闭**不属于安全保证**，仅非默认运维模式）。
- WebSocket 继续 501（`proxy.py:9-13` 已就绪，不动）。
- 路径表**写死**（来自 B0 §1.3，不臆造）。

**匹配策略**（设计决策 A，见 §8）：
- 前缀匹配 `/pty` 与 `/api/pty`（覆盖两棵 PTY 树全部 HTTP 路径）。
- 模式匹配 `/session/{sid}/shell`（regex `^/session/[^/]+/shell$`）。
- method-agnostic（任意方法命中即 deny，defense in depth）。

**诚实限制**：catch-all 不识别路径语义是结构性事实；deny-list 是 best-effort 第二道，真实隔离靠 stunnel mTLS + 网络边界 + upstream 权限。漏路径即可绕过。

### 3.5 错误码结构化迁移（cross-cutting）

**落点**：`sessions.py` 5 处 `HTTPException`（`:59, :61, :103, :131, :140`）+ `questions.py` 4 处（`:27, :99, :102, :113`）。

**目标**：body 统一 `{"code":string, **fields}`（spec §11）。

**机制**（设计决策 B，见 §8）：引入 `CodedHTTPException(HTTPException)` + FastAPI `exception_handler`，渲染 `{"code":…, **fields}`。
- 让 helper（如 `require_directory`）继续 `raise`（不改控制流）。
- 9 处站点改抛 `CodedHTTPException(code=..., status_code=..., **fields)`。
- `messages.py` 现有 `return error_response(...)` 保持不变（已是正确形状）。
- 不动 `versioning.py` / `proxy.py` / `events.py`（已 `{"code":…}`）。

**code 命名**（spec §11 统一表）：`directory_not_allowed`(400) / `session_not_found`(404) / `upstream_unavailable`(503) / `upstream_http_N`(502) / 及 questions 既有的入参/routeToken/超时码。
