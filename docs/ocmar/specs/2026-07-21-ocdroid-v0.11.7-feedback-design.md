# ocdroid v0.11.7 契约反馈改造方案 v2（修订评审稿）

> **v2 修订**：v1 经 gate-1（rev-glm 9.0 / rev-bgpt 3.0）**均未过 9.5**。rev-bgpt 提出颠覆性事实——**上游 legacy `/session` 的 `start` 是 `time_updated >= start` 时间戳水位，非 offset 偏移**（已亲自核验 `packages/opencode/src/session/session.ts:561, 990-991`；handler `handlers/session.ts:64-74`；`ListQuery` 仅 `scope/path/roots/start/search/limit`，**不暴露前向 cursor**）。v1 的 §1.2 `cursor=encode(start+limit)` 前提错误。v2 据用户决策大幅收窄：
> - **§1**：砍 cursor/`?cursor=`；保留诚实的 `X-Complete` + 重命名 `X-Discovery-Directories`；修 `start` 时间戳语义文档；**roots 默认不翻**（文档建议客户端显式传 `roots=true`）。
> - **§2**：**不去 placeholder**；仅契约确认 partId 稳定性（文档级）。
> - **§3**：`server.reconfigured` 成**唯一权威 cold-start 信号**；**上游重连不发 `resync`**（`resync` 仅留订阅者背压 / Last-Event-ID no-replay）；`load_products` 加 single-flight+代际+去重。
> - **§4**：加性 `schema.version/clientMin/clientMax`；**删「能力探测」承诺**（仅 wire 范围回显）。
>
> 全程**不 bump `X-Slimapi-Version`**（维持 `1`）；v2 已剔除所有破坏性默认/body 形状变更。评审门控：本稿经 **rev-glm + rev-bgpt ≥9.5** 通过后实施。

## 0. 上游分页事实（v2 基线，已源码核验）

| 事实 | 源码定位 | 含义 |
|---|---|---|
| legacy `/session` list 用 `Session.Service`（非 `SessionV2`） | `handlers/session.ts:50` | 走 `Session.list` → `listByProject` |
| `start` = `gte(SessionTable.time_updated, input.start)` | `session.ts:561, 990-991` | **时间戳水位下界**（epoch ms），非数组 offset |
| `cursor` = `lt(SessionTable.time_updated, input.cursor)` | `session.ts:562` | 服务层支持上界，**但 legacy HTTP `ListQuery` 不暴露**（`groups/session.ts:30-38`） |
| 排序 `desc(time_updated), desc(id)` | `session.ts:574, 1003` | 无快照锚点；并发插入/更新/归档会影响排序与重复 |
| 默认 `limit=100`（service 侧 `?? 100`） | `session.ts:575` | sidecar `Query(100, ge=1, le=1000)` 一致 |
| 现契约 §2 称「`start` 偏移分页」 | `v1-contract.md:44` | **stale/错误**（pre-existing 文档 bug），v2 修正 |

**结论**：legacy `/session` HTTP API **不支持前向分页**（无上界 cursor 暴露）。`start` 是「只看 time_updated ≥ start 的最新 N 条」水位。客户端无法翻页取「更老」的会话——只能提高 `limit` 或收窄 `start`。ocdroid 现已用 `limit=500`（feedback §1 `7dc5134`），单页覆盖绝大多数场景。

## §1 `GET /slimapi/sessions` — 完整性头 + start 文档修正（纯加性）

### 1.1 新增响应头（仅 200；错误响应不发）

| 头 | 语义（**诚实、可证**） | 计算 |
|---|---|---|
| `X-Complete` | **「本页未满」信号**：`true` 当且仅当上游返回条数 `< limit`。语义**仅**为「在本次查询条件（`directory`/`roots`/`search`/`start` 水位）下，匹配集合未填满 `limit`」；**不**等同于「权威全集」（上游无 total/快照，时间戳分页+并发变更使其不可证）。`false` 表示「≥ limit 条匹配，可能截断；客户端可提高 `limit` 或收窄 `start` 复查」。 | `len(sessions) < limit` → `true`；否则 `false`。每次 200 都发。 |
| `X-Discovery-Directories` | **sidecar 发现就绪度**（**重命名**，避 q/p `scope.directories` 歧义）：= `len(app.state.directory_allowlist)`。`0` = 发现未就绪（启动早于 opencode / 暖机未完成）；`>0` = 发现就绪。**明确不是**「本次 query 命中 dir 数」（`/sessions` 不 fan-out），**不是** q/p 的 fan-out scope 数。 | 整数；每次 200 都发。 |

- **`X-Next-Cursor` / `?cursor=` / `invalid_cursor`：全部砍除**（上游不支持前向分页，合成 offset cursor 是 v1 的错误）。
- 头命名用 `X-Discovery-Directories`（非 `X-Scope-Directories`），并在契约 §2 + CLIENT_CHANGES 用**三列对照表**写死：`端点 × 头/字段名 × 语义`，明确 `/sessions` 此头 = 全局发现集大小（readiness），q/p `scope.directories` = 实际 fan-out 命中数——同名族但语义不同。
- 上游异常 shape（非 list / 坏 JSON）已走 503（既有），不发完整性头。

### 1.2 `start` 语义文档修正（pre-existing stale 修复，无行为变更）

- 契约 §2 `/sessions` 行：把「`start` 偏移分页」**勘误**为「`start` = epoch-ms 时间戳水位（`time_updated >= start`，上游 legacy 语义），非 offset；默认不传 = 0 = 全部；用于收窄查询窗口，**非**翻页」。
- sidecar 代码 `sessions.py:87` `start: int | None = Query(None, ge=0)` **不变**（ge=0 对 epoch-ms 水位同样合理）；仅文档修正。`params["start"] = start` 透传不变。
- **`roots` 默认保持 `False`**（v1 想翻 True，已撤回）：契约 + CLIENT_CHANGES 增「客户端**应显式传** `roots=true` 以排除 subagent/task 子会话；依赖默认会拿到子会话扇出」的建议。ocdroid 已显式传（`7dc5134`）。

### 1.3 实现落点

- `routes/sessions.py` `sessions()`：200 响应增加两头（`X-Complete` = `str(len(sessions) < limit).lower()`；`X-Discovery-Directories` = `str(len(app.state.directory_allowlist))`）。`json_response` 已支持透传 headers（见 messages.py 用法）；此处经 `accept_encoding` 路径需确认头注入点。
- 无新 query 参数；无 cursor 编解码；无 `roots` 默认改动。

## §2 partId 稳定性 — 契约确认（仅文档，无代码变更）

### 2.1 稳定性 ratify（源码已证）

- **有可渲染 part 的消息**：thin skeleton 经 `_pick(part, PART_IDS)`（`PART_IDS` 含 `"id"`，`skeleton.py:9`）保留每个 part 的**真实 `id`**；该 `id` 在 `/full/{mid}`（单条 `mode=full` 透传 / `mode=skeleton` 复用 `skeleton_message`）与 `/full?ids=`（batch）中原样出现。**partId 跨 thin/`/full` 端点稳定**——契约显式 ratify。
- **无可渲染 part 的消息**：保留既有合成 placeholder（`thin_placeholder_{message_id}`，`skeleton.py:145-154`）——**v2 不移除**。契约显式标注：该 placeholder 是 **message-level UI 兜底**，**不参与** `/full` 的 `messageId+partId` 对齐；客户端展开 `/full` 后应**整体替换该 message 的 parts**（而非按 placeholder partId 原地替换）。

### 2.2 边界裁定

- v2 **不改** `skeleton.py`（无 body 形状变化、无 subtype 风险）。移除 placeholder 的诉求（feedback §2 方案 A）**转入 backlog**，待后续与 ocdroid 协调的发版窗口再做（届时需逐 subtype 验证真实 `prt_*` id + `hasFull` 不变量 + 客户端先行适配）。本批仅在契约/CLIENT_CHANGES 写明现状与未来方向。

### 2.3 实现落点

- 无代码变更。契约 §5 / CLIENT_CHANGES「消息加载与展开」节补 partId 稳定性保证 + placeholder 的 message-level 替换语义说明。

## §3 SSE `server.reconfigured` — 唯一权威 cold-start 信号（加性 + 重连信号迁移）

### 3.1 帧定义与权威性

- event：`server.reconfigured`；payload `{reason: <enum>, at: <epoch-ms int>}`。
  - `reason` 枚举：`"upstream_reconnect"`（上游 `/global/event` 重连）/ `"allowlist_changed"`（allowlist 发现集变更）。未知值客户端须前向兼容（不作分支依据）。
  - `at` = sidecar 收到/生成时刻 epoch-ms（非上游事件时间）。
- **客户端契约**：`server.reconfigured` 是**唯一权威 cold-start 触发信号**（作废本地 commitToken / stale 状态，走冷启动重拉）。
- `resync` **保留但仅用于**：① 订阅者队列/字节背压（`hub.py:234` `subscriber_backpressure`）；② 订阅者带 `Last-Event-ID` 连接时的 `reconnect_no_replay`（`events.py:39`）。**上游重连不再发 `resync`**（消除 v1 双重 cold-start）。

### 3.2 触发实现

| 触发 | 现状（hub.py） | v2 改造 |
|---|---|---|
| **上游成功重连**（drop 后重建 stream） | `run()` `if self.ever_connected: reconnects_total+=1; resync_all()`（502-504） | **改为** `notify_reconfigured("upstream_reconnect")`（**不发 resync**） |
| **上游异常/掉线**（except 分支） | `if self.ever_connected: resync_all()`（519-521） | **改为**：不发任何帧（仅退避重试）；重连成功由上一行 `upstream_reconnect` 统一通知。消除「一次故障多次信号」。 |
| **allowlist 变更** | 无 | `load_products()` 原子提交后 set-equality 比对；变化才 `notify_reconfigured("allowlist_changed")`；hub 无订阅者时 no-op（**不惰性创建空 GlobalHub**——检查 `hubs._global is not None and hub.subscribers`） |

### 3.3 `load_products` 并发护栏（pre-existing bug 修复，两位评审共识）

- 现状：`load_products()`（`sessions.py:18-53`）无并发协调；`/projects` + q-p null-dir 刷新 + 启动暖机可并发，后完成的旧快照可覆盖新快照 → 伪 `allowlist_changed` 或漏发。
- v2 改造：
  1. **single-flight**：模块级/`app.state` 级 `asyncio.Lock` 串行化 `load_products`（并发调用复用同一 in-flight 结果，或排队）。
  2. **代际（generation）**：每次启动 `load_products` 取当前 `app.state.allowlist_generation` 快照；提交前校验自己仍是最新代（latest-wins）；旧代结果丢弃。
  3. **原子提交 + set-equality 去重**：在新结果与 `app.state.directory_allowlist` 比对后，仅当 set 变化才写入 + `notify_reconfigured`；相同 set 不通知（高频 `/projects` 下抑制刷屏）。
  4. 失败（upstream 错）不改 set、不通知。

### 3.4 T3 背压兼容

- `server.reconfigured` 是普通 sized frame，经 `subscriber.put`，纳入订阅者字节/帧预算；满队列/临界预算时走既有 overflow 路径（`resync{subscriber_backpressure}`+STOP，不变）。补测试：满队列下发 reconfigured 不破坏既有背压契约 + `emitted_frames_total` 计数正确。

### 3.5 实现落点

- `sse/hub.py`：新增 `notify_reconfigured(reason)` 方法（遍历 `subscribers` `put` `sse_frame({"reason":reason,"at":_now_ms()}, event="server.reconfigured")` + `emitted_frames_total` 累加）；`run()` 重连路径（502-504）调之、except 路径（519-521）删 `resync_all()`。
- `routes/sessions.py` `load_products()`：加 `asyncio.Lock` + generation 校验 + set-equality diff + `app.state.hubs.get_global()` 存在且有订阅者时 `notify_reconfigured("allowlist_changed")`。
- 契约 §3 + CLIENT_CHANGES SSE 节：新增 `server.reconfigured` 帧 + 权威性 + 重连信号迁移说明（`resync` 重连用途退役，仅留背压/no-replay）。

## §4 `/health` + `/ready` schema 回显（纯加性）

### 4.1 body 扩展

`schema` 节由 `{degraded}` 扩展为 `{degraded, version, clientMin, clientMax}`：

```json
"schema": {"degraded": <bool>, "version": 1, "clientMin": 1, "clientMax": 1}
```

- `version` = `SERVER_API_VERSION`；`clientMin`/`clientMax` = `accepted_client_versions` 的 min/max（从 `app.state.config` 读，**非硬编码**）。
- 原 `server.api_version` / `server.accepted_client_versions` **保留**（不删，向后兼容）。

### 4.2 删除「能力探测」承诺

- v2 **不宣称**「客户端可据此动态探测 cursor/reconfigured 等能力」（version 保持 1 则新旧服务端三元组相同，无法探测）。契约 §1 仅说明：此三元组是 **wire 兼容范围回显**；additive 变更不动 `version`，破坏性变更才 bump 并扩 `clientMax`/升 `clientMin`。

### 4.3 实现落点

- `routes/health.py` `health()` + `ready()`：`schema` 节加三键（从 config 读）。`/ready` 503 时字段同样保留。
