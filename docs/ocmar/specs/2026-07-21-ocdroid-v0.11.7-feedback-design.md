## 0. 上游分页事实（v3 基线，已源码核验并修正）

| 事实 | 源码定位 | 含义 |
|---|---|---|
| legacy `/session` list 用 `Session.Service`（非 `SessionV2`） | `handlers/session.ts:50` | 走 `Session.list` → `listByProject` |
| `start` = `gte(SessionTable.time_updated, input.start)` | `session.ts:561, 990-991` | **epoch-ms 时间戳水位下界**，非 offset |
| `cursor` = `lt(SessionTable.time_updated, input.cursor)` | `session.ts:562` | 服务层支持，**但 legacy HTTP `ListQuery` 不暴露**（`groups/session.ts:30-38`） |
| **排序（legacy /session 经 listByProject）** | `session.ts:1003` | **`desc(time_updated)` 仅此一项，无 id tie-break**（v3 修正 v2 错误：`desc(id)` 只在 `listGlobal:574`，非本路径） |
| 默认 `limit=100`（service 侧 `?? 100`） | `session.ts:575, 997` | sidecar `Query(100, ge=1, le=1000)` 一致 |
| 现契约 §2 称「`start` 偏移分页」 | `v1-contract.md:44` | **stale/错误**（pre-existing 文档 bug），v3 修正 |

**结论**：legacy `/session` HTTP API **不支持前向分页**（无上界 cursor 暴露），且**不保证 id tie-break**（同 `time_updated` 的相对顺序未定义——客户端不得据 id 排序推导）。`start` 是「只看 time_updated ≥ start 的最新 N 条」水位；客户端无法翻页取更老会话，只能提高 `limit` 或收窄 `start`。ocdroid 现已用 `limit=500`（`7dc5134`），单页覆盖绝大多数场景。

## §1 `GET /slimapi/sessions` — 完整性头 + discovery readiness + start 文档修正（纯加性）

### 1.1 新增响应头（仅 200；错误响应不发）

| 头 | 语义（**诚实、可证**） | 计算 |
|---|---|---|
| `X-Complete` | **「本页未满」信号**：`true` 当且仅当上游返回条数 `< limit`。语义**仅**为「本次查询条件（`directory`/`roots`/`search`/`start` 水位）下匹配集合未填满 `limit`」。**契约强制语言**：客户端**不得**据此头判定「权威全集」「权威空」「覆盖完整性」或「结束冷启动」（上游无 total/快照、无 id tie-break、时间戳分页+并发变更，均不可证）；`false` 仅意味着「≥ limit 条匹配，可能截断，可提高 `limit` 或收窄 `start` 复查」。 | `len(sessions) < limit` → `true`；否则 `false`。每次 200 都发。 |

## §3 SSE `server.reconfigured` — 纯加性新权威帧（仅 allowlist 变更；重连 resync 不动）

### 3.1 帧定义与权威性（v3 定局）

- event：`server.reconfigured`；payload `{reason: <enum>, at: <epoch-ms int>}`。
  - `reason` 枚举（v5 收窄为**仅一项**）：`"discovery_changed"`（v5 由 `allowlist_changed` 改名，更准——涵盖「目录集合变更」**与**「discovery 就绪态 false→true 过渡」两类，见 §3.2 通知条件）。未知值客户端须前向兼容（不作分支依据）。**注**：`upstream_reconnect` reason **不引入**——上游重连继续走既有 `resync`（见 3.2）。
  - `at` = sidecar 生成时刻 epoch-ms。
- **客户端契约**：`server.reconfigured{reason:"discovery_changed"}` 是 **discovery 变更（集合变 **或** 就绪态变）的唯一权威 cold-start 触发信号**（作废本地 commitToken / stale，走冷启动重拉）。
- **`resync` 完全不动**（v3 关键）：上游重连仍发既有 `resync{reason:"reconnect_no_replay"}`（`hub.py:502-504` success / `519-521` except 双路径保持现状）；订阅者背压 `resync{subscriber_backpressure}`（`hub.py:234`）、Last-Event-ID no-replay（`events.py:39`）全部不变。
- **为何无双重 cold-start**：`server.reconfigured` 与 `resync` 触发**不同、不重叠**的事件（前者 allowlist 变更，后者上游连接断/重连/背压）；任何单一事件只发一个帧。

### 3.2 触发实现（仅 allowlist 变更）

| 触发 | 现状 | v3 改造 |
|---|---|---|
| 上游成功重连 | `resync_all()`（`hub.py:502-504`） | **不动**（保持 resync） |
| 上游 except/掉线 | `resync_all()`（`hub.py:519-521`） | **不动**（保持 resync） |
| **discovery 变更**（集合变 **或** 就绪态变） | 无 | `load_products()` 原子提交后比对；**通知条件（v5 修正，回应 bgpt round-4 #1）= `(new_set != old_set) OR (old_ready is False AND new_ready is True)`**——覆盖「目录集合变更」**与**「就绪态 false→true（即便集合仍空，如启动暖机失败→空，后成功发现权威空）」两类；命中才经 `hubs.notify_reconfigured_if_active("discovery_changed")` 直推（hub 无活跃订阅者时 no-op，**不惰性创建 GlobalHub**）；未命中（集合同 + ready 已 true）不通知（主抑制路径）。 |

### 3.3 `load_products` 并发护栏（pre-existing bug 修复，v3 简化为纯 Lock）

- 现状（`sessions.py:18-53`）：无并发协调；`/projects` + q-p null-dir 刷新 + 启动暖机可并发，后完成旧快照可覆盖新快照 → 伪 `allowlist_changed` 或漏发。
- v3 改造（**single-worker asyncio 下最简且充分**）：
  1. **`app.state.allowlist_lock = asyncio.Lock()`（v4 定稿实例，v5 措辞修正，回应 bgpt round-4 非阻塞）**：在 lifespan 创建（紧邻 `allowlist_ready`）；**锁在 `load_products(app)` 内部 `async with app.state.allowlist_lock:` 获取一次**，覆盖「fetch upstream + 校验 shape + 写 `directory_allowlist` + 比对 + notify」整段。**三调用方（`warm_allowlist` `sessions.py:65`、`/projects` `:125`、q-p null-dir fan-out `questions.py:46-47`）仅调用 `load_products(app)`，不在调用方再加锁**（避免非重入 Lock 双重加锁死锁）。并发调用排队（A 跑完才轮到 B），无交错覆盖。不用模块级锁（避免跨 app/test 串扰）。测试 fixture 同步初始化该 Lock。
  2. **通知条件 + set-equality 去重（v5 修正，回应 bgpt round-4 #1）**：提交时记 `old_set = app.state.directory_allowlist`（copy）、`old_ready = app.state.allowlist_ready`；写入 `new_set`、（成功时）置 `new_ready = True`；**通知条件 = `(new_set != old_set) OR (old_ready is False AND new_ready is True)`**——集合变 **或** 就绪态 false→true（即便集合仍空）才 `notify_reconfigured_if_active("discovery_changed")`；集合同且 ready 已 true → 不通知（主抑制路径）。
  3. **首次成功置 ready**：函数末尾（成功）置 `app.state.allowlist_ready = True`（支撑 §1.1 `X-Discovery-Ready`）。失败不改 set、不置 ready、不通知（ready 已 True 时保持 last-known-good，不复位）。
  4. **`load_products` shape 校验（v5 顶层 + v6 per-directory，回应 bgpt round-4 #2 / round-5 #1）**：
     - **顶层** `/project`：`sessions.py:22` 后加 `if not isinstance(projects, list): raise <refresh failure>`（在 `gather` 前）。
     - **per-directory** `/project/{id}/directories`（v6 修正）：现状 `sessions.py:29-31` 是 **`if isinstance(raw_directories, list) else []` 静默降级**（非失败守卫）——dict/string/null 等 200 坏 shape 会被当空目录 → 不完整 `new_set` 覆盖 last-known-good + 可能伪 `discovery_changed`。v6 改为 decorate 内 `result.json()` 后 **`if not isinstance(raw_directories, list): raise <refresh failure>`**，由 `asyncio.gather` 传播 → **整次刷新失败**；保留旧 set/ready、不通知、不写 `new_set`。
     - 坏 shape（顶层或任一 per-directory 非 list）一律按刷新失败处理。补测试：顶层非 list（首次 + ready=true 后）；**per-directory 非 list**（dict/string/null，首次 + ready=true 后）——断言旧 set/ready 不变、无 `server.reconfigured`。
  5. **删除 v2 的 generation 计数器**（round-2 评审共识：Lock 跨全函数后代际冗余）。
- **极端 stale-fetch 边缘（v4 承认，glm 非阻塞#4）**：A 持锁慢 fetch 旧快照先提交、B 排队后 fetch 新快照——A 提交时 set-diff 可能触发一次幂等伪 notify，B 再提交触发第二次。罕见（需上游在两 fetch 间变更 + 时序交错）且 cold-start 幂等，可接受；主抑制路径（连续相同 allowlist→0 帧）有测试锚定。可选：为 refresh 等待加 metrics/log 便于发现慢上游队头阻塞（bgpt 非阻塞）。

### 3.4 outage / sidecar-restart 文档化（v3 新增，回应 round-2 阻塞）

- **heartbeat ≠ 上游健康**：`server.heartbeat`（10s，`hub.py:339-346`）仅证明 sidecar 进程存活 + 订阅连接在，**不证明**上游 opencode 可达。上游掉线期（`hub.run()` except 退避重试中），客户端仍收 heartbeat，但上游实际不可用。
- **outage 探测**：客户端不应仅凭 heartbeat 判「一切正常」；主动探测委托 `GET /slimapi/ready`（ping 上游 `/global/health`）或自然 fetch/write 失败（`upstream_unavailable` 503）。
- **恢复信号**：上游重连成功 → 既有 `resync{reconnect_no_replay}`（不变）触发 cold-start。
- **sidecar restart**：进程重启 = SSE 连接断开；客户端重连 → 收 `server.connected`（订阅欢迎帧，`hub.py:297`）。契约 §3 明确：**`server.connected` 即隐含「新连接、状态可能已变」**，客户端**应**将其视为 cold-start 触发（无条件执行初始快照）；不依赖任何「重启帧」。
- **连接建立期 single-flight reconciler（v4 新增，v5 措辞软化，回应 bgpt round-3 #1 / glm round-4 非阻塞#3）**：`server.connected`（`subscribe` 入队，`hub.py:297`）与 Last-Event-ID `resync`（`events.py:38-39` 在 generate() 首帧 yield）在带 Last-Event-ID 的重连上**会同时出现**——这是既有行为（v4/v5 不改两路径）。契约规定：**客户端 SHOULD 对「同一 SSE 连接建立期」（per-connection-generation）的 cold-start 触发帧（`server.connected` 欢迎 + 同连接首条 `resync`）做 once-latch coalescing**——至多触发**一次** reconcile（reconcile 幂等，coalescing 是避免冗余重拉的优化，非正确性必需；服务端继续按现状发两帧，零变更）。补服务端测试：带 Last-Event-ID 连接上两帧均可见（协议事实）；客户端 coalescing 在 ocdroid 侧验证（移交文档列确认项：带 Last-Event-ID 的客户端级 once-latch 测试）。

### 3.5 T3 背压兼容

- `server.reconfigured` 是普通 sized frame，经 `subscriber.put`，纳入订阅者字节/帧预算；满队列/临界预算走既有 overflow 路径（`resync{subscriber_backpressure}`+STOP，不变）。
- **`Subscriber.put` 返回值改造（v4 新增，v5 边界精确，回应 bgpt round-3 #3 / round-4 非阻塞 / glm round-4 非阻塞#2）**：现状 `put(frame)`（`hub.py:200-237`）返 `None`，调用方无法判定「成功入队 / closed 丢弃 / 超大帧丢弃 / overflow 替换为 resync」。v5 改 `put` 返 **`bool`**，各退出点精确：
  - `closed` 早返 → `False`；
  - `STOP` 哨兵 → `try: put_nowait(STOP); return True; except QueueFull: return False`（**v5 明确**：仅在实际入队成功才 True）；
  - 超大帧（`size > max_frame_bytes`）→ `dropped_frames+=1; return False`；
  - 正常入队（`queue.qsize() < items and queued_bytes+size <= buffer_bytes`）→ `put_nowait` 成功 → `queued_bytes+=size; return True`，撞 `QueueFull` → 落 overflow；
  - overflow 路径（自产 resync+STOP）→ `return False`（**原帧未入队**，overflow 自产的 resync/STOP 不经本次返回值计 metric）。
  `emitted_frames_total`（`notify_reconfigured` 内）**仅在 `put` 返 True 时累加**。`put` 的字节账本（`queued_bytes`）与 overflow 行为**完全不变**，仅加返回值。
- **`emitted_frames_total` 混合计数语义（v5 文档标注，glm round-4 非阻塞#1）**：`notify_reconfigured` 经 `put` 返 bool 精确计数；但既有 `flush`/`heartbeat_loop`/`publish`/`resync_all`（`hub.py:336-337, 345-346, 368-369, 473-474, 483-484`）仍用 `+= len(self.subscribers)` 粗放计数（背压下过计）。属 **pre-existing** 观测面问题、非 v5 引入；契约/ops 文档标注「该 metric 混合语义」，后续可统一（backlog）。

### 3.6 实现落点

- `sse/hub.py`：新增 `HubRegistry.notify_reconfigured_if_active(reason)` **公有方法**（避免外部模块触 `_global` 私有）：`if self._global is not None and self._global.subscribers: return self._global.notify_reconfigured(reason); return 0`；`GlobalHub.notify_reconfigured(reason)` 遍历订阅者 `put` `sse_frame({"reason":reason,"at":_now_ms()}, event="server.reconfigured")`，**仅 `put` 返 True 才** `emitted_frames_total` 累加（§3.5），返回通知计数。`Subscriber.put` 改返 bool（§3.5）。

## §4 `/health` + `/ready` schema 回显（纯加性，定位为诊断回显）

### 4.1 body 扩展

`schema` 节由 `{degraded}` 扩展为 `{degraded, version, clientMin, clientMax}`：

```json
"schema": {"degraded": <bool>, "version": 1, "clientMin": 1, "clientMax": 1}
```

- `version` = `SERVER_API_VERSION`；`clientMin`/`clientMax` = `accepted_client_versions` 的 min/max（从 `app.state.config` 读，**非硬编码**）。
- 原 `server.api_version` / `server.accepted_client_versions` **保留**（向后兼容）。
- **关系澄清（v3）**：`X-Slimapi-Version`（请求头，wire 门禁）= `server.api_version` = `schema.version`（三者当前均 = 1，兼容映射）；`clientMin/clientMax` = `accepted_client_versions` 闭区间。三者独立概念、当前值相等是兼容映射而非同义。

### 4.2 删除「能力探测」承诺（v3 坚持）

- **不宣称**「客户端可据此动态探测 cursor/reconfigured 等能力」（version 保持 1 则新旧服务端三元组相同，无法探测；且 `version_incompatible` 错误已回传 `accepted:[min,max]`，versioning.py:48-54）。
- 定位为：**诊断用 wire 兼容范围回显**（运维 / 非错误路径内省），**非 feature discovery**。保留（加性、低成本、有诊断价值）。

### 4.3 实现落点

- `routes/health.py` `health()` + `ready()`：`schema` 节加三键（从 config 读）。`/ready` 503 时字段同样保留。
