## 1. messageID 纯透传 — ✅ CONFIRMED

ocdroid `(updatedAt, messageID)` 字典序 tie-break 依赖 messageID 字典序严格单调（= opencode 原始发射顺序）。slimapi 全路径对 messageID（= opencode `info.id`）做 verbatim 透传，无重映射、无重排、无重生。

| 路径 | 源证（file:line） | messageID 处理 |
|---|---|---|
| skeleton 投影（`/messages`、`/since`） | `src/oc_slimapi/skeleton.py:142` `result = {"info": deepcopy(message.get("info", {}))}` | `info` 整体 deepcopy，`info.id` 原样 |
| skeleton parts | `skeleton.py:9` `PART_IDS` 含 `messageID`；`_pick` → `deepcopy(value[key])`（`:21`） | part 的 `messageID` 字段原样 |
| `/full` full mode（batch + single） | `routes/messages.py:398` `StreamingResponse(response.aiter_raw(), ...)` | 纯字节流透传，零解析、零改写 |
| `/full` skeleton mode | `routes/messages.py:579` `skeleton_message(orjson.loads(b))` | 同 skeleton 投影 |
| transform 链 | `transform.py:85-100` `project_and_pack` / `project_messages_and_pack` → `skeleton_message(s)` | 全程不触碰 id |
| **SSE digest fan-out**（ocdroid 关切的聚合层） | `sse/hub.py:415` `message_id = info.get("id") if isinstance(info.get("id"), str) else props.get("messageID")` → `:422` `entry.message_id = message_id` → `:148` `payload["messageID"] = self.message_id` | digest 帧 `messageID` = 上游 `info.id` 原样；`props.messageID` 仅作 malformed 非-str id 兜底，仍是上游原值 |
| q/p fan-out（`_aggregate`） | `routes/questions.py:60-66` `enriched = dict(item)` + 仅注入 `directory` / `routeToken` | 不触碰 `id`/`messageID`/`requestID`（且 q/p item 非 message tie-break 维度） |

**唯一合成 id**：`thin_placeholder_{message_id}`（`skeleton.py:146-154`），仅在消息无可渲染 part 时注入。这是 **part 级 id**，且其 `messageID` 字段 = 真实上游 messageID；不参与、不影响 ocdroid 的 message 维 tie-break。

**诚实保留**（非阻塞，handoff §6 已声明）：digest 的 `updatedAt` 在 `info.time.updated` 与 `created` 双缺时落 `_now_ms()` 兜底（`hub.py:417`），而 `/since` 过滤的 `_item_updated` 同情况返 `None`（`messages.py:218`）。该差异仅影响 `updatedAt` 维度（tie-break 主键），**不触碰 messageID**；opencode v1.18.3 实际恒发 `info.time.created`，属 malformed 边角。

**结论**：messageID 字典序单调性 = opencode 原始单调性，slimapi 不破坏。ocdroid tie-break 语义安全。

## 2. `Partial + scope.directories==0` 是否可能 — Partial 不可能 / Success 可能

slimapi q/p wire 只有两种状态：**200（含 `scope`）** 或 **503 全失败（无 `scope`）**。"Success / Partial" 是 ocdroid 对 200 响应按 `errors[]` 是否为空做的客户端分类（slimapi wire 层无该命名）。

### 推演（`routes/questions.py:_aggregate`）

- `scope.directories = len(checked)`（`:83`）
- `checked` 来源：
  - 显式 `directory` → 规范化去重后列表，受 `invalid_directory_count` 守卫（`:32-33`）→ 恒 ≥1
  - `null` → `sorted(allowlist)`（`:46`），**可为 `[]`**
- `status = 503 if results and len(errors) == len(results) else 200`（`:77`）

### 组合可达性

| 组合 | 可达性 | 依据 |
|---|---|---|
| **Partial（200 + `errors` 非空）+ N==0** | **不可能** | `errors` 非空 ⇒ 至少 1 个 `fetch` ⇒ `checked` 非空 ⇒ `len(checked) ≥ 1` |
| **Success（200 + `errors` 空）+ N==0** | **可能** | `null` dir + 空 allowlist → `checked=[]` → `results=[]`（`gather` 空输入）→ `status=200` → `scope.directories=0` |

### 冷启动 N==0 真实可达

- `app.py:54` `app.state.directory_allowlist = set()` —— 启动即空。
- `_aggregate` 在 allowlist 空时 best-effort 调 `load_products` 刷新（`questions.py:41-44`），但若 opencode 未起 / 返空 → `checked` 仍为 `[]`。
- **契约权威**：`v1-contract.md §2`（line 176）显式定义「空 allowlist → 200 `{"items":[],"errors":[],"scope":{"directories":0}}`」。
- **单测锚定**：`tests/test_questions_routes.py:186-196` 字面断言 `response.json() == {"items": [], "errors": [], "scope": {"directories": 0}}`。
- 503 全失败路径**不含** `scope`（`questions.py:82`）：`tests/test_questions_routes.py:272` 锚定。

**结论**：ocdroid 的 N==0 retain-prior gate 设计正确——
- **Success 分支 = 必要**（真实冷启动态，契约定义 + 单测覆盖）；
- **Partial 分支 = 无害防御**（结构上不可能）。

安全超集成立，**无需任何一侧改动**。

## 3. `/sessions` 错误体消费深度 — 最小深度 = 契约正确

### slimapi `/sessions` 列表失败路径（`routes/sessions.py:104-118` + `_raise_upstream_status :150-161`，list 端无 `sid`）

| 上游情况 | slimapi 响应 | body（§11 `{"code":...}`） |
|---|---|---|
| 网络错（`httpx.RequestError`） | 503 | `{"code":"upstream_unavailable"}` |
| 4xx（含 404） | 502 | `{"code":"upstream_http_N"}`（404 → `upstream_http_404`，**非** `session_not_found`——list 端无 sid 上下文） |
| 5xx | 503 | `{"code":"upstream_unavailable"}` |
| 200 + 坏 JSON / 坏 shape | 503 | `{"code":"upstream_unavailable"}` |

body 统一经 `CodedHTTPException` 渲染为 `{"code":..., **fields}`（`errors.py:33-38`）。

### slimapi 立场

handoff §2 item2 已写明：「若按"非 200=失败"粗判，行为不变」。codes 是为与 `/sessions/{sid}/status`、`/projects` 保持一致的 **observability 面**，**不**承载分支契约。

**结论**：ocdroid 当前 `parseErrorCode`→internal + log + rethrow 原始 = **契约正确的最小深度**，无需协商 carrier、无需按 code 差异化。若未来 ocdroid 主动想差异化（如 503 可重试 / 502 不重试），carrier 已就位，可直接按 `code` 分支——属 ocdroid 调用方决策，slimapi 不强制、不期望。

回归测试锚定：`tests/` 覆盖 `upstream_http_N` / `upstream_unavailable` code log+rethrow 路径（见 handoff §3 行 503/502）。
