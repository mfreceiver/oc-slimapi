## 1. 本批交付（ocdroid 视角）

### v0.2.1 — ratify ocdroid 提出的 3 个契约遗留缺口 + 修 2 个 pre-existing 真 bug

ocdroid 在 v0.2.0 后核对契约，提出 3 个遗留缺口（Gap1 tie-break / Gap2 空-失败区分 / Gap3 `/since/0`）。slimapi 侧 explorer 源码核验发现 Gap1/Gap2 背后藏着 2 个 pre-existing 真 bug，一并修：

| # | 缺口 / bug | 处置 |
|---|---|---|
| **Gap1** | 等时间戳不同 messageId tie-break 未定义 | 定义 tie-break = `(updatedAt, messageID)` 二元组字典序（对齐上游 `(time_created DESC, id DESC)` 全序，复用上游单调 `MessageID`） |
| **Gap1 真 bug** | `/since/{ts}` 时间过滤 **no-op**（契约写 `time.updated >= ts`，但 opencode v1.18.3 message schema **无** `info.time.updated` 字段，过滤键落空） | `_item_updated` 改读 `info.time.updated or info.time.created`（与 digest `updatedAt` 同源）→ 过滤真正生效 |
| **Gap2** | cold-start "成功空" vs "失败" wire 层不可区分 | q/p 缺口**不成立**（已可区分）；`/sessions` 列表发现真实 §7 偏离（见下） |
| **Gap2 真 bug** | `/slimapi/sessions` 列表失败路径偏离 §7（upstream 4xx/5xx 原样透传、网络错落 FastAPI 默认 `{"detail":...}` 500、零测试覆盖） | 对齐 sibling（`/sessions/{sid}/status`、`/projects`）：4xx→502 `upstream_http_N`、5xx/网络→503 `upstream_unavailable`、200+坏 JSON/坏 shape→503，body 均 `{"code":...}` |
| **Gap2 加性** | q/p envelope 无法区分 "scope 未就绪 / 权威空" | 200 envelope 加 `scope: {directories: N}`（N=有效 scope dir 数） |
| **Gap3** | `/since/0` 推荐路径未表态 | §5 补注：无 watermark 初始拉取推荐 cursor drain（`?before` 分页）而非 `/since/0` |
| **额外（rev-13 捕获）** | q/p 显式 directory 未规范化去重（`/app`+`/app/` 双 fan-out）；`/sessions` 200+坏 JSON→非结构化 500 | 规范化后去重 + 复刻 sibling 坏 JSON→503 防御 |

## 2. ocdroid 侧须关注（客户端改动清单，按优先级）

> 详尽行为描述见 [`docs/specs/CLIENT_CHANGES.md`](../../specs/CLIENT_CHANGES.md)；契约权威见 [`docs/specs/v1-contract.md`](../../specs/v1-contract.md) §14.6。

1. **`/since` 过滤修复 + watermark 升级（Gap1，最高优先）**
   - sidecar `/since/{ts}` 此前是 **no-op**（对任何 ts 返回最新 N 条），现真正按 `(info.time.updated or info.time.created) >= ts` 过滤。v1.18.3 下与 digest `updatedAt` 都解析到 `info.time.created`。
   - **ocdroid 须把 per-session watermark 从标量 `max updatedAt` 升级为 `(updatedAt, messageID)` 二元组字典序**：先 strict 比 `updatedAt`（严格 `>` 才推进时间维），相等时 strict 比 `messageID`（`msg_+ascending()` 单调，新消息 id 字典序更大）。解 strict-advance 在等时间戳不同 id 的残留 bug。
   - **`/since/0` 虽合法，但无 watermark 的初始拉取推荐 cursor drain（`?before` 分页）**。

2. **`/sessions` 列表错误体（Gap2）**
   - 失败路径此前**静默偏离** §7（upstream 4xx/5xx 原样透传、网络错→FastAPI 默认 `{"detail":...}` 500）；现统一 coded：4xx→502 `upstream_http_N`、5xx/网络→503 `upstream_unavailable`、200+坏 JSON→503，body 为 `{"code":...}`。
   - 若 ocdroid 已按 `code` 解析（如 status/projects），sessions 列表现同样处理；若按"非 200=失败"粗判，行为不变。

3. **q/p envelope `scope` 字段（Gap2，加性，可选消费）**
   - 200 响应含 `scope: {directories: N}`：
     - `N == 0` → **scope 未就绪**（allowlist 空，sidecar 启动早于 opencode）→ 冷启动**不**清本地 stale，等 scope 就绪后重拉。
     - `N > 0 && items == []` → **scope 就绪、权威空** → 可清本地 stale。
     - `N > 0 && items != []` → 正常 pending。
   - 503 全失败响应**不含** `scope`。
   - 旧客户端忽略此字段仍可工作（加性）。

4. **q/p 显式 directory 规范化去重（客户端可观测）**
   - `?directory=/app&directory=/app/` 现按规范化后去重 = 1 个 dir（不再双 fan-out / 双 routeToken）。
   - `invalid_directory_count` 守卫语义改为按**规范化后 fan-out 数**判定（33 个 raw dir 去重 ≤32 → 200，旧 raw-dedup 行为 → 400）。

## 5. 联调建议（ocdroid 验证要点）

- **`/since` 真过滤**：用真实 watermark 拉 `/slimapi/messages/{sid}/since/{ts}`，验证返回 **子集**（≥ ts 的项），而非全量。旧 no-op 会返回全部 + messageID 去重兜底；修复后严格按 ts 过滤。
- **tie-break**：构造同 `updatedAt` 不同 `messageID` 的边界（上游并行/批产），验证 `(updatedAt, messageID)` 二元组推进无残留。
- **q/p cold-start scope**：sidecar 启动早于 opencode 时 `scope.directories=0`（不清 stale）；`GET /slimapi/projects` 刷新 allowlist 后再拉 → `scope.directories>0`。
- **`/sessions` 列表失败**：upstream 5xx → 503 `upstream_unavailable`（不再透传 500 body）；网络断 → 503 coded（不再 FastAPI 默认 `{"detail":...}`）。
- **`/sessions` list 404**：upstream `/session` 返 404 → **502 `upstream_http_404`**（**非** `session_not_found`，因 list 端无 sid 上下文）。

## 6. 已知非阻塞保留项（诚实声明）

- `_item_updated` 的类型守卫（`isinstance(raw,int) and not isinstance(raw,bool)`）比 digest（hub.py 无守卫）略严格——happy path（epoch-ms int）等价，仅 malformed 字符串时间戳防御性差异。
- `_item_updated` 用 `item.get("info") or {}`（挡 falsy），hub.py 用 `isinstance(...dict)`——opencode 实际总发 dict，benign 边角差异。
- `message.appended` 事件在 v1.18.3 不发射（hub MESSAGE_EVENTS 保留作 forward-compat）。
- 三审 🟡 单项（非字典 item 防御测、tie-break client-vs-server 措辞）已记入跟踪，非本批验收条件。
