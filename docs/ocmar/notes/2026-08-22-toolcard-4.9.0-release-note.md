> 权威契约：`docs/specs/v4-contract.md` §10.2 修订四 + §14.2；行为清单：`CHANGELOG.md` [4.9.0]
> 背景：oc-webui `TOOL_CARD_CONTRACT_PROPOSAL.md` 四项提案的服务端落地（经生产 DB 实证 + 两轮独立评审）

## 一句话总结

工具卡四缺陷中三项已在服务端根治（patch 全空 / compress 折叠空 / edit 丢 diffStats），一项搁置（P0-2，前提不成立）；**ocdroid 与 oc-webui 现行版本均零必改**——你们的客户端兜底方案（展开空回退折叠内容等）可保留但不再是必需。

## 逐项变更（对客户端可观察行为）

### 1. patch files 归一化（修「patch 全空」）⚠️ wire 形状变更

`GET /slimapi/messages/{sid}` skeleton 中 patch part 的 `files`：上游 `string[]` → **对象数组**：

- string 条目 → `{"path": <s>}`；legacy object 条目 → `{path, additions, deletions, status}` 照旧
- **cap 10**：有效条目超 10 截为前 10，附 `filesTotal` = 源数组长度（源计数，含无效条目）；未超限不附
- `filesTotal` 与条目数的差 ≠ 可展示文件数差——畸形条目也计入 filesTotal

**兼容性**：ocdroid `Part.kt` PartFilesSerializer 与 oc-webui `PartCards.vue` toFiles 均已双形状兼容（已实证），**零必改**。若有第三方严格按 `string[]` 解析需改为双形状。

### 2. tool metadata.files compact 投影（修「apply_patch 卡信息缺失」）

`state.metadata` 投影增 `files` 键（此前被白名单整体丢弃）：

- compact 映射：`{path: relativePath ?? filePath, additions?, deletions?, status: type}`——剔除 `patch` diff 正文（~700B/条）
- cap 10 + `metadata.filesTotal`（同上口径）
- **ref 恒在**：源 `metadata.files` 非空 → `part_state_metadata_full` ref 必发（完整清单可展开获取）

### 3. edit diff 合成注入（修「edit 卡无 files/diffStats」——提案外增量）

生产实证 edit 的 `metadata.filediff` 恒为空 `[]`（22,967/22,967），原 diffStats 注入对 edit 从未生效。现从 `metadata.diff` 文本（git diff 格式）状态机解析合成：

- skeleton 注入 `metadata.files`（`{path, additions, deletions}`，同 cap 10/filesTotal/ref 管线）+ diffStats
- **expand 通道**：`part_state_metadata_full` 对 edit 返回**无 cap** 完整合成 `files`——skeleton 被 cap 截断的第 11+ 条经展开端点可达
- `truncated == true` 的 edit 不合成（宁缺毋假）；`state.metadata.diff` 本身仍省略（字节不变）

### 4. compress title 合成（修「compress 折叠空」）

`tool=="compress"` 且 state 无 title 时：`clip(topic, 160) ?? clip(summary, 160) ?? "压缩 {N} 段"`。topic 优先（人类撰写标题，生产 avg 28 字符）。仅 skeleton 视图；merged splice 后恢复上游原状。

### 5. outputBytes（P2-4）

tool state `output` 因预算省略时附 `state.outputBytes` = JSON wire 字节数（含引号/转义）。可做「内容多大、值不值得展开」提示。

### 6. ETag 全量轮换（无需动作，知悉即可）

skeleton 表示域 `v1 → v2`：升级后旧 v4 ETag 全部自然失效、客户端条件请求全量重拉一次（预期内一次性流量，304 语义照常工作）。

## 搁置项：P0-2（patch 纳入 expand ref 体系）

生产 DB 实证 patch part **0/23,827 带 state**——上游就是 `{hash, files}`，patch state 省略的场景**永不触发**，emit ref 无对象可指。搁置；重启条件 = 上游 opencode 真给 patch 加 state（届时契约再议）。

## 验证与性能

- 3549 项测试全绿（含 5 条真实 expand 路由测试、ETag 轮换、merged 三 lane 回归）
- diff 解析器生产样本实测：随机 400 条 P95=0.037ms / max=4.1ms；最大 20 条（≤36KB）max=8.0ms——单遍线性，无缓存必要
