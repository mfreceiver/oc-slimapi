## 1. 基线与已闭环（评审时默认成立）

### 1.1 slimapi v0.3.0 已交付（服务端）

| 能力 | Wire 要点 | 客户端须知 |
|---|---|---|
| sessions 三头 | 200 only：`X-Complete` / `X-Discovery-Directories` / `X-Discovery-Ready` | Complete **≠** 权威全集；Ready=false **≠** 权威空 |
| SSE `server.reconfigured` | `{reason:"discovery_changed", at}` | 与 resync **分层**；收到 → cold-start |
| health schema 三键 | `schema.version/clientMin/clientMax` | **诊断**，非 feature discovery |
| partId ratify | 真 part 跨 thin/full 稳定；`thin_placeholder_*` 不参与 part 对齐 | **message-level** 替换 |
| G6 batch | `GET …/full?ids=`（1–20） | 主路径 batch + 单条 fallback |
| 去 allowlist gate | directory normalize 透传 | `directory_not_allowed` **仅** query/header 冲突 |
| 明文 `:4097` | 可 `0.0.0.0` | 安全靠 Tailscale ACL / 防火墙；14097 仍推荐 mTLS |

### 1.2 ocdroid 已声明落地（相对 rev F，**v0.11.10 已发版上线**）

| # | 移交项 | 客户端状态（ocdroid 自报） |
|---|---|---|
| 1 | placeholder → message-level 替换 | **已做** |
| 2 | `server.reconfigured` → cold-start | **已做** |
| 3 | 连接建立 once-latch / dirty coalesce | **已做** |
| 4 | sessions 三头消费 | **已做** |
| 5 | 显式 `roots=true` | 本就有 |
| 6 | G6 batch 主路径 | 本就有（含 404 fallback） |
| 7 | health schema 三键 | **未做**（可选） |

### 1.3 已裁定、本计划默认**不重开**的决策

| 决策 | 结论 |
|---|---|
| Wire API | 维持 **1**（全加性路径） |
| `roots` 默认 | **保持 false**；客户端显式 `roots=true` |
| `X-Complete=false` | **不强制**客户端二次分页；`limit=500` 兜底可保留 |
| Ready=false + 空列表 | **keep prior sessions** |
| reconfigured vs resync | 语义不重叠；合法窗口可各冷启动一次（客户端幂等） |
| 去 placeholder | **backlog**，需联合发版窗口 |
| sessions body envelope / 前向 cursor | **不做**（方案 B 未采纳） |

### 3.2 M-1 — 去 placeholder（中期主协议候选）

| 字段 | 内容 |
|---|---|
| **详情** | thin 在无可渲染 part 时**不再**注入 `thin_placeholder_{messageID}`，改为直接返回真实折叠 part（或空 parts + 明确约定）。设计已标 backlog。 |
| **意义** | 消除「合成 id」特殊路径；展开逻辑可统一 part-level；长期降低客户端分支。 |
| **slimapi 任务** | 设计确认（subtype × hasFull 不变量）→ 改 `skeleton.py` → 契约/CLIENT_CHANGES/CHANGELOG → 测试矩阵 → 发版。 |
| **ocdroid 任务** | **先**保证 message-level 路径在占位仍存在时正确；去 placeholder 后：回归「无可渲染 part」消息；删除仅服务 placeholder 的分支（可保留兼容一段时间）。 |
| **配合** | **联合发版窗口**：建议顺序 (1) 客户端已 message-level 上线稳定 → (2) slimapi 去 placeholder → (3) 客户端清理。评估是否需短暂双支持。 |
| **风险** | 漏 subtype 导致「无 UI 可点」；旧 APK 若仍 part-level 对齐 placeholder 会再挂——故须最低客户端版本说明。 |
| **决策问题（请评审）** | 是否纳入下一 minor？是否要求最低 ocdroid 版本？是否保持 wire=1？ |

## 4. 远期（P3）— 契约 §10 与 v2 方向

> **目标**：记录方向，**不承诺工期**；立项时另开 design。  
> **来源**：`v1-contract.md` §10、design-v2 可选优化、历史 G3-B 等延后项。

| ID | 主题 | 详情 | 意义 | slimapi | ocdroid | 备注 |
|---|---|---|---|---|---|---|
| L-1 | skeleton 共享缓存 | 进程内按 mid 缓存 thin | 降 CPU/延迟 | 指标驱动再做 | 无感或 ETag | YAGNI 先指标 |
| L-2 | 多用户 / 多 stack | 独立 allowlist/SSE | 多租户 | 大架构 | 大架构 | 非 v1 |
| L-3 | durable SSE replay | Last-Event-ID 真重放 | 弱网体验 | 大 | 消费 replay | 现 resync=冷启动 |
| L-4 | circuit breaker（服务端） | 对 upstream 熔断 | 保护 sidecar | 可选 | 客户端已有 GET CB | 边界需划清 |
| L-5 | sessions 前向 cursor / envelope | 真分页 | 超大列表 | 依赖上游 | 重写列表同步 | **上游无 cursor 时不做假分页** |
| L-6 | Part 展开 UI 深化 | 与 M-8 相关 | 省流率 | skeleton 规则 | UI | 产品驱动 |
| L-7 | 可观测增强 | tracing / 结构化审计 | 运维 | 逐步 | 诊断上报 | §10 metrics 之外 |
| L-8 | Wire v2 | 破坏性整理 | 长期简洁 | bump 门禁 | 强制升级路径 | 仅当加性无法承载 |

## 7. 风险与非目标

### 7.1 风险

| 风险 | 缓解 |
|---|---|
| 客户端未发版，线上仍旧逻辑 | 发版节奏优先；文档标明「需 ≥ ocdroid x + slimapi 0.3.0」 |
| 用 `sidecar.version` 误判能力 | 以行为探针（三头/帧）为准；发版后务必 reinstall editable |
| Ready 与列表竞态 | 客户端 Ready=false keep prior；服务端 last-known-good 不复位 |
| reconfigured + resync 双冷启动 | 客户端幂等；不合并跨层信号 |
| 去 placeholder 踩旧 APK | 联合窗口 + 最低版本 |
| 文档双源 | 冲突以 slimapi 契约 + CHANGELOG 为准 |

### 7.2 本周期非目标（明确不做）

- 破坏性 bump `X-Slimapi-Version`（无充分理由）  
- sessions body 改 envelope / 伪造前向 cursor  
- durable SSE replay / 多租户  
- 以 schema 三键做 feature discovery  
- 为「完整」而翻 roots 默认
